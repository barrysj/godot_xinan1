# 功能实施文档

这里记录各项功能**目前如何实现、验证到了哪里、还缺什么**，不是 session 日志，也不是排期。每个稳定功能 ID 只有一份主档案，同一功能跨 session 更新同一文件。

- 看项目整体：[实现总览](../implementation-status.md)。
- 看未来安排：[Roadmap](../roadmap.md)。
- 查验证命令与已有结果：[共享验证目录](verification.md)。
- 改跨系统接口前：[集成约束](integration.md)。
- 玩法与数值继续在原主题文档维护，美术批准仍在美术任务与 Manifest，不在此复制。

## 维护分工

1. 功能 session：先读总览，再定位本目录相关档案及主题规范；完成后更新状态、实现入口、验证日期／基线／命令／结果、已知边界。新增能力使用未占用的稳定 ID 创建档案，并登记下表。
2. 若引用共享检查，同步 verification.md 中对应项；不要只记录“测试通过”，必须注明覆盖范围和未测项。历史结果保留适用版本，当前失败不能被旧 PASS 掩盖。
3. 影响全局流程、平台支持、依赖或范围时，在功能档案“交接给统筹”标注“待统筹”及具体影响。普通功能 session 不直接改总览或 Roadmap，除非用户明确要求其同时承担统筹。
4. 统筹 session：核对变更的功能档案与实现，更新总览日期／基线、整体能力与断点；仅里程碑／范围／优先级变化时修改 Roadmap，并把已消费的待统筹标记更新为汇总日期。
5. 总览是最近一次统筹快照，可能晚于功能档案；有差异时按最新可验证代码、功能证据裁决，不为追求一致擅自提升完成状态。Git 记录历史，不按日期复制功能文件。

状态用词：已验证、已实装、部分实装、原型、仅设计、待核验、已替代。定义见总览。新文档沿用现有档案栏目，不预建空任务；相关能力确需拆分时分配新 ID，保留旧 ID 的迁移说明。
