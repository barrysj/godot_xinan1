### 混合动画资产包归一（仅设计，待实施）

骨骼＋序列帧角色采用“候选完整记录、正式运行子集”的同构结构。候选与正式目录中的运行核心必须具有相同文件角色：`presentation.tscn` 保存骨骼层级、枢轴、遮挡和挂点，`animations.tres` 保存骨骼关键帧，`battle_animation.tres` 保存统一入口与序列帧回退，帧元数据、部件图和图集随资源保存。普通角色不得复制专用表现控制脚本；共享控制器由工程稳定路径提供。确有动态骨骼或其他无法数据化的角色才允许小型扩展脚本，并必须在资源契约中显式登记。

候选版本继续保留 `generation.md`、`review/` 与 Codex 工作流证据；正式 `assets/art/` 不包含评审 GIF、截图、临时捕获帧、角色专用构建脚本或 Python 缓存。正式路径不带版本号，由批准候选通过确定性提升工具复制运行文件、重写项目资源引用并校验文件角色、动作集合、依赖和 Manifest。当前 HEAD 的直接复现依靠候选资源与兼容的 schema；批准时实现的精确追溯依靠 Git 基线，不在每个候选中复制旧控制器源码。

粉笔精灵 006 目前尚未完成上述数据化迁移：候选和正式表现仍各有专用脚本／场景，正式表现位于 `scenes/battle_demo/presentations/`。迁移完成前保留这些仍被 `.tres` 与角色资源引用的文件。目标实现与验收矩阵见 [ART-03 推荐改造](art-03.md#推荐改造骨骼序列帧通用生产与预览仅设计待实施)。
