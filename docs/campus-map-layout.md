# 校园全图地点与路线编辑

试用全图的单一数据源是 [`game/run/expanded_campus_layout.json`](../game/run/expanded_campus_layout.json)。源图坐标为 1800×1500，左上角是 `[0,0]`，向右 x 增大，向下 y 增大；无论运行窗口如何缩放，都只改这里的源图坐标。保存后重新启动地图预览查看结果。

## 可视化编辑器

在项目根目录的 PowerShell 7 终端启动开发工具集，点击“地图编辑”卡的“启动”，再点“打开”：

```powershell
pwsh.exe -NoProfile -File .\run-tool-suite-control.ps1
```

默认地址是 `http://127.0.0.1:8767/`。工具集显示实时状态、PID 和运行目录；关闭工具集窗口不会停止地图服务，完成编辑后可点“停止”。服务只监听本机 `127.0.0.1`。也可不用工具集，直接执行 `pwsh.exe -NoProfile -File .\tools\campus-map-editor\run-server.ps1`；若需另选端口，用 `-Port 8768`，但工具集只检测默认的 8767 端口。纯 Node 调试可执行 `node tools/campus-map-editor/server.mjs --port 8768`，在终端按 Ctrl+C 关闭。

1. 选当前路线，再选“区域边界”“路线节点”或“地点”。直接拖动地图圆点；Shift＋点击边线插入顶点。“加点”插在所选顶点之后，“删点”删除所选顶点。
2. 调整地图边缘明暗时，切换到“亮区边界”：黄色闭合线内保持原亮度，线外变暗。拖动黄色顶点、Shift＋点击边线加点；右侧可调日／夜／异常三态的校外亮度和边缘过渡宽度。编辑器画布即时显示日间明暗，夜间和异常请保存后在游戏预览中切换查看。它不等于真实测绘校界，也不改变路线选区或可通行范围。
3. “路线内地点”可勾选地点和调整顺序。下方可改地点名称、精确 X/Y 坐标，或给当前路线添加新地点。路线名称、颜色和既有战役对应关系也可编辑。
4. 用“撤销／重做”检查结果；点击“保存地图”才会写入游戏布局文件。每次保存前，旧版自动备份在 `.godot/campus-map-editor-backups/`。也可“导出”JSON 副本；“导入”后仍须点“保存地图”才会生效。
5. 保存会拒绝越界坐标、缺失地点引用、自交区域和超过 32 点的边界。如果另一个程序已改动该文件，编辑器会拒绝覆盖；先导出自己的版本，再刷新页面核对。

这是桌面端开发工具，不会出现在玩家游戏内。当前不提供新战役区域的创建；新增视觉路线仍只能映射到已有三个战役 ID。编辑器的“路线内地点”顺序与地图上画出的 `path` 线是两组独立数据，需要分别调整。

## 指定位置交流

在编辑器点击「取坐标」，再点地图上的目标位置。黄色十字标记固定落点，右侧「指定位置」显示原图坐标；点击「复制坐标」即可把 `x=1080.7, y=749.9` 这样的文本发到聊天中。「清除」只清除标记；点击任一编辑对象按钮回到编辑模式。

坐标与布局共用1800×1500原图空间，不受缩放或滚动影响，不是屏幕像素或经纬度。拾取不修改地图，不需要保存，也不进入撤销记录；刷新页面后标记消失。自动复制受浏览器限制时，输入框会选中文字，可手动按Ctrl+C。

## 直接编辑 JSON

- 改地点文字或落点：在 `places` 中找到 ID，改 `title` 或 `point`。例如 `"library": {"title":"图书馆", "point":[720,755]}`。
- 新增地点：在 `places` 中添唯一英文 ID、文字和坐标，并把这个 ID 放到某条路线的 `places` 列表。地图上的地点标记与文字会自动出现。
- 改路线途经地点：调整路线的 `places` 顺序。路线文字名称改 `title`；显示用的线条是 `path`，需按源图顺序列出至少两个 `[x,y]`。`places` 不会自动生成线条。
- 改高亮范围：调整 `area` 多边形顶点，沿边界顺时针或逆时针依次写入，不要自交，至少 3 点、最多 32 点。首尾无需重复。该范围同时用于鼠标命中和区域高亮，不等于可通行导航网格。
- 改校外降亮度：调整顶层 `light_boundary.points` 闭合多边形，线内原亮度、线外按 `outside_brightness.day/night/anomaly` 分态降低亮度；`feather` 是源图像素单位的过渡宽度。它独立于每条路线的 `area`。为了使拖动能真正恢复已压暗区域，游戏使用未烘焙压暗的三态底图，明暗在运行时计算。编辑器画布近似显示日间效果，不模拟过渡羽化。
- 改战役对应：`campaign_region` 当前仅接受 `library`、`region_b`、`region_c`；这只是既有三段战役入口，不会创建新战役。新路线可映射到其中之一。

手动编辑时，先复制一份 JSON 作备份。注意英文双引号、逗号和中括号；无效坐标、缺失地点引用、重复路线 ID 会被拒绝。地点和路线目前仍为试用数据，不能据此推断真实步行路线。
