# 校园纪念游戏设计案

版本：v0.3 · 战斗 Demo 阶段 · 2026-09-06

本稿依据《确定游戏形式栈》对话与当前工程整理。标记为“已确认”的内容来自用户明确表述；其余均为本轮提案，数值是供验证的起点，不代表已经定案或经过平衡测试。本文优先定义玩家体验与游戏规则，工程实现应在关键规则讨论后启动。

## 1. 项目定位与决策状态

一句话概念：同学们重返被异次元侵入的母校，通过路线选择、小队构筑和自动战斗找回校园的记忆，并逐步恢复学校。

| 内容 | 状态 | 说明 |
|---|---|---|
| 班级毕业周年纪念主题 | 已确认 | 原对话明确提出；具体周年、学校与班级名称待提供 |
| 异次元入侵校园，同学作为角色或 NPC | 已确认 | 入侵缘由、敌人形象、结局尚未确定 |
| 局内 Roguelike＋自走棋，局外成长 | 已确认 | 需要设计可重复探索的价值 |
| 互动集中在成长、选路、编队、装备、道具 | 已确认 | 战斗为全自动棋子交互 |
| GGT 模板作为工程起点 | 已确认且本地核实 | 当前仍是菜单与示例 gameplay |
| 尽可能兼容多设备、方便分发 | 已确认目标 | Web 主入口为原对话建议，实际设备验收待做 |
| 三周工期 | 原对话约束，待复核 | 需补充截止日、每日可投入时间与协作人数 |

| 胜利后恢复全部战斗状态 | 本轮已确认 | 全员归队，无胜利战损累积；具体状态重置见第 5 节 |
| 先用虚构角色完善规则 | 本轮已确认 | 暂不限制最终同学规模 |
| 2D、固定阵型、4 人上阵、横屏 | 提案 | 原对话提出过，尚未逐项确认 |

体验目标：玩家既能认出熟悉的人与地方，也能理解一次调整为什么让战斗变得更顺利。纪念内容需要进入技能、事件选择和校园变化，而不只放在图鉴里。

首版成功标准提案：首次玩家在 3 分钟内完成一次编队与战斗；完整探索目标为 20～30 分钟；一次失败仍能留下明确进展；普通主线可用初始阵容通关，不要求重复刷取数值。

难度结构：主线承担完整剧情与主要纪念内容，额外挑战提供策略压力，此方向已确认。具体挑战规则提案为通关后每局自选一个条件，例如“敌方生命＋20%”或“每区域增加一个精英节点”；挑战模式限制重试次数，具体次数后续确定；首版只实现一个经试玩验证的条件，不叠加难度阶梯。挑战奖励为记录或纪念标记，不独占主线结局与重要人物内容。

## 2. 情绪、世界与叙事

基调提案：轻松、热闹、带一点奇幻，结尾温柔。校园的异常可以夸张，同学间的熟悉感要真实。

背景提案：周年重聚时，校园的地点和往事发生重叠。走廊通向不同年份的教室，广播重复着未结束的通知，操场的终点不断后退。同学们从安全教室出发，寻找维系异常的“记忆锚点”。

主线分三步：发现校园异常 → 在不同地点找回同学与共同经历 → 解除最终异常，在恢复的校园重聚。入侵是外部灾害还是记忆具象化，留作叙事选择，不在本稿强行解释。

恢复有两种表现：本局击败区域 Boss 后，该区域暂时恢复；首次完成区域目标后，基地永久解锁对应纪念场景。后续探索是清理残留裂隙，不把已经找回的同学和记忆再次“遗忘”。

建议结局：熟悉的铃声响起，所有同学以适合各自的形式回到纪念画面。主线结局不要求刷满全部收集；图鉴与彩蛋提供后续探索理由。

所有人物、地点、事件名称在真实素材提供前使用占位称呼。梗的呈现以本人愿意分享的正面特征和共同经历为基础。

## 3. 核心循环

```text
基地：查看修复成果、解锁选择、整理出发阵容
  ↓
开始探索：选初始同学与一项出发补给
  ↓
地图选路 → 节点预览 → 战前准备 → 自动战斗／事件／商店
  ↑                                           ↓
  └──────── 获得奖励、调整构筑 ────────────────┘
  ↓
区域 Boss → 后续区域 → 最终 Boss
  ↓
结算：保存修复进度与回忆、获得局外资源 → 基地
```

每一步的决策问题：下一条路能补足什么？谁上场、站哪里？稀缺装备给谁？道具现在用还是留给 Boss？本轮带回的资源优先解锁什么？

## 4. 战斗一页规则（提案）

| 项目 | 规则起点 |
|---|---|
| 棋盘 | 双方各 3 列×2 排；我方最多 4 人，敌方最多 6 人 |
| 移动 | 固定槽位；攻击位移仅为演出，不改变逻辑站位 |
| 编队 | 战前可换人、换位、换装；开战后锁定 |
| 操作 | 战中可暂停查看、切换 1×／2×，角色技能自动释放 |
| 普攻 | 按攻击间隔触发；首次普攻等待一个完整间隔 |
| 基础数值 | 生命、攻击、防御、攻击间隔；索敌规则单独描述 |
| 技能 | 每人一个特色技能；先以每完成 3 次普攻后自动触发为统一原型 |
| 胜利 | 敌方全部退场且我方仍有存活角色 |
| 失败 | 我方全灭；同一结算时点双方全灭按失败处理 |
| 时限 | 单场目标 30～60 秒；90 秒仍未决出胜负按失败处理，开战前可知 |
| 胜利后（已确认） | 全员归队并恢复完整战斗状态，无退场惩罚；局内装备与强化保留 |

技能触发为何先选攻击计数：玩家容易理解“再攻击一次就放技能”，也方便看懂装备价值。能量制保留为替代方案；若角色需要受击蓄能等差异化机制，再讨论引入。两种机制不同时叠加。

普通索敌顺序：同列敌方前排 → 其他前排 → 同列后排 → 其他后排。并列目标先按列距离，再按固定槽位编号裁决。即使自身位于后排，也能按规则普攻，避免固定格子出现无法交战。

特殊索敌只通过明确的技能或角色规则提供，例如优先后排、最低生命比例、整排攻击。最低生命比例的并列情况仍用固定槽位裁决。相邻指同侧上下左右相邻，斜角不算。

伤害初始公式：`max(1, round(攻击 × 技能倍率 × 100 / (100 + 防御)))`，首版防御不低于 0。护盾先吸收伤害，治疗不超过生命上限。首版仅保留伤害、治疗、护盾与属性增益，暂缓反伤、复活、技能复制和复杂控制连锁。

同一逻辑时点的行动先形成待结算集合，再统一应用伤害与退场，避免节点处理顺序左右结果。动画速度不能改变伤害、攻击次数或胜负。

战斗应显示“为什么”：攻击目标连线或短促弹道、技能名、护盾量、死亡状态；结算展示主要伤害／治疗贡献与一条可核对的事实，如“敌方后排造成了最多伤害”，不伪造因果分析。

## 5. 胜利恢复与失败边界

已确认原则：只要战斗胜利，全队恢复全部战斗状态，不因残血、退场人数或战斗用时留下战损。即使只有一人存活，也按正常胜利处理。

状态重置的具体口径：所有退场角色归队，生命恢复上限；负面状态、临时增益和临时护盾清空；普攻计时与技能触发计数回到新战斗初始值。若后续改为能量制，能量同样重置为开战初值，而非直接充满。装备提供的常驻效果在下一场重新应用。

局内角色、装备、训练与已获得奖励保留。恢复战斗状态不返还已消耗道具或花费的金币，也不移除明确持续整局的构筑效果。

撤回旧稿的“胜利按退场人数扣士气”方案，暂不引入独立士气系统。路线风险主要来自下一场能否获胜，以及是否值得花道具换取更好的奖励；治疗与护盾服务于当场胜利，不承担战后修复职责。

已确认：主线失败后可以无限重试，挑战模式才限制次数。具体挑战次数后续再定，当前优先验证核心战斗。战斗 Demo 失败后可立即恢复初始战斗状态、重新编队并再次挑战，不设置重试费用。

主动撤离提案：只能在非战斗阶段进行，保留已获得的局外资源，不补发未获得的通关奖励。

## 6. 招募、阵容与构筑

初始提案：从已解锁角色中选 3 人出发；教学提供默认阵容。第一场安全战后保证获得第 4 人。最多上阵 4 人，候补 4 人。

招募奖励给出 2 名当前尚未拥有的候选，选 1 名；候补已满时可放弃招募，或先选一人离队，装备退回背包。首版不做重复角色合成、升星与共享卡池。

角色差异优先来自“攻击谁、保护谁、与什么位置配合”，避免只有攻击和生命不同。

| 虚构原型 | 作用 | 技能示例 | 需要的构筑选择 |
|---|---|---|---|
| 守护者 | 承伤 | 为自身与左右相邻友军加盾 | 放在前排中央，但需注意范围攻击 |
| 远射手 | 处理后排 | 对后排单体造成伤害 | 用装备保证其存活或加快技能节奏 |
| 应援者 | 恢复 | 治疗生命比例最低的友军 | 与护盾或高生命角色配合 |
| 冲刺手 | 收割 | 攻击生命比例最低的敌人 | 需要队友先压低目标生命 |

羁绊列为扩展项：首版最多 3 组双人关系，每组只有一个效果、面板明确提示。若延期，保留同队语音或文本彩蛋即可。真实人物分配不绑定强弱稀有度。

## 7. 装备与道具

装备：每人 1 个槽，局内背包提案上限 12 件，战前免费调整。无耐久、无强化、无随机词条。背包满时新奖励允许替换或放弃；被替换物品消失前明确提示。

装备样例仅用于说明方向：篮球鞋缩短攻击间隔；厚笔记本增加生命；纪念徽章提高治疗量。首版以简单属性效果为主，少量条件效果作为后续内容。

道具：携带上限 3 件，每场最多使用 1 件战斗道具。推荐在战前选定目标并确认使用，开战时自动生效；玩家无需在混战中找时机点击。确认开战时才扣除道具。

首版道具效果提案为战前护盾、开局削弱敌人、下一场攻击强化；不设置战后回血或恢复士气道具。道具数量归零、目标无效、背包已满等情况必须有明确反馈。

讨论分支：若你希望“道具使用”包含战中干预，可改为暂停后使用、每场一次；这仍保留角色自动战斗，但会增加玩家关注战况的负担。

## 8. 地图、节点与局长

默认讨论规模：2 个区域，每区走过 6 个节点，其中最后一个为 Boss；每层 2～3 个候选，仅可沿连线前往下一层。全局约 7～9 场战斗，目标总时长 20～30 分钟，实际需试玩计时。

地图使用预制连线骨架，随机替换允许变化的节点内容。确保所有可选节点从起点可达且能通向 Boss，每条路径都有构筑补强机会，禁止连续精英。区域地貌与节点内容匹配，例如操场出现运动器材与对应记忆。

| 节点 | 玩家决策 | 产出与风险 |
|---|---|---|
| 普通战斗 | 是否为奖励承受战损 | 基础货币与奖励选择 |
| 精英战斗 | 更高收益是否值得 | 强敌、较高货币、明确预告的装备奖励 |
| 同学事件 | 招募谁或选择哪种帮助 | 招募／装备／金币取舍 |
| 记忆事件 | 在 2 项可理解的结果间选择 | 短剧情、局内资源、首次回忆解锁 |
| 商店 | 花费还是留钱 | 3 件固定商品，无付费刷新 |
| 整备 | 强化角色还是补充道具 | 一次训练选择，或获得一个道具；不承担回血功能 |
| Boss | 检验本区构筑 | 区域恢复、局外奖励、下一地区 |

战斗前展示敌方阵型、招牌技能、节点奖励类别；地图展示节点类型和路径。随机来自遭遇组合与奖励，避免同一个看似安全的节点无预告变成致命惩罚。

奖励原型：普通胜利获得 10 金币，加一个三选一奖励；精英 20 金币加装备选择；Boss 30 金币加区域奖励。奖励卡可来自装备、招募或“给一名角色本局生命／攻击＋10%”的训练，训练每人最多 2 次。所有选项非法时改发固定金币。

商店价格起点：道具 10、装备 20、招募 25。正式定价要和整条路线产出一起测算，以上不是平衡结论。

## 9. 局外成长与纪念收集

局内金币、装备、训练与临时招募在探索结束后清空；局外修复资源、已解锁角色、回忆、首次区域恢复永久保留。

成长优先扩展选择：解锁初始可选同学、不同出发补给、校园回忆页面。暂不设置士气或战后恢复相关升级；是否需要数值成长另行讨论，主线不以购买永久数值提升为前提。

经济起点：每次普通胜利获得 1 修复点、精英 2 点、区域 Boss 3 点，结算时转入局外；首个横向解锁成本 5 点。失败和撤离都保存已赢得的修复点。首次回忆只记录一次。失败重试不会重复获得未获胜节点奖励。

永久校园展示分为“通关里程碑恢复的地点”和“花修复点解锁的设施功能”，界面分别说明，避免两种进度混淆。纪念内容不因失败倒退。

## 10. 界面与视听

主界面：继续探索／开始探索／校园与回忆／设置。地图、准备、战斗、奖励、事件、结算分别有单一主要操作。

战前页以敌我阵型为中心，候补、装备和道具采用切换面板；点击角色再点击槽位即可换位，拖拽只是可选快捷方式。技能信息可点开，不依赖悬停。

横屏为待确认提案，手机竖屏打开时给出旋转提示。布局应按实际手机可读性测试，不能只把 1920×1080 桌面画面缩小。优先保证姓名、技能摘要、生命与开战按钮清楚可点。

视听预算：头像或半身像作为棋子，轻量攻击位移、受击闪白、技能名与统一特效；区域恢复前后切换背景细节。先做 1 套共享战斗表现，再按重要角色补专属演出。

音乐在玩家进入游戏后开始；暂停面板控制音量和速度。文本可跳过也可在回忆中重读。首版不依赖配音。

## 11. 一次具体游玩示例

玩家带守护者、远射手和应援者出发，在教学战后招募冲刺手。地图分出“精英＋商店”和“事件＋整备”两条路，玩家判断当前阵容能应对精英并希望购买装备，选择前者。

预览发现敌方后排治疗者，玩家把攻击节奏装备交给远射手，把守护者放在前排，并使用开局护盾道具。战斗自动进行，远射手优先处理治疗者，冲刺手收割残血。胜利时退场 1 人，该角色战后归队，全员恢复完整战斗状态，不产生战损惩罚；已使用的护盾道具不返还。

玩家用金币在商店买下 Boss 战补给。Boss 的整排攻击促使玩家分散布阵，首次取胜后该区域的校园背景恢复，解锁一段回忆。这个过程需要让玩家看懂“预览 → 调整 → 结果”的关联。

## 12. 内容范围与三周安排（工期待复核）

| 层级 | 内容预算 | 完成标准 |
|---|---|---|
| 最小可玩闭环 | 4 名角色、3 类普通敌人、1 Boss、1 区域、4 装备、2 道具、2 事件、1 局外解锁 | 新局到结算完整可玩，含失败、续玩、再次出发 |
| 纪念首发目标 | 8 名战斗角色、6 类普通敌人、2 Boss、2 区域、8 装备、4 道具、6～8 事件、1 结局 | 关键纪念内容完整、目标设备可玩 |
| 可选扩展 | 更多同学、双人羁绊、额外难度、更多回忆 | 仅在首发目标稳定后加入 |

本轮决定先用虚构角色验证规则，最终人物数量不设定案。表中人数是开发预算提案，不能视为已确认的出场上限。后续确定人物覆盖方式时重新估计头像、文案与测试工作量。

## 16. 当前战斗 Demo（v0.3）

用户要求优先确定核心战斗并制作 Demo，暂缓非核心细节。场景：`scenes/battle_demo/battle_demo.tscn`；菜单 Play 已连接该场景。

本次实现用于试玩验证：双方各 3×2 固定格，我方 4 人；点击角色再点格子交换／移动；一件篮球鞋可分配给任意同学；每 3 次普攻自动释放技能；守护者给自身与正交相邻友军护盾，远射手攻击后排，应援者治疗低血量友军，冲刺手追击残血。普通攻击遵循前排优先、同列优先规则。

提供“守卫与治疗”和“整排攻击”两组敌阵，可暂停和切换 1×／2×。金色连线表示技能，卡片显示生命、护盾、技能计数。胜利立即恢复我方全员；失败可无限返回编队重试。Demo 无存档，不消耗局内资源。

实现口径：技能在第 3 次普攻同一逻辑步触发；同一步先收集全部行动，再结算护盾／治疗，最后统一处理伤害与胜负。护盾累计上限暂为 144。当前战斗长度由原型数值决定，尚未按正式版 30～60 秒目标调参。

已做本地 Godot 4.7.2 无界面实跑：初始阵型对守卫组失败，调整为前排中央守护者、右侧冲刺手，后排左侧远射手、中央应援者后，装备给守护者／远射手／应援者均可胜利，给冲刺手则失败。说明此组原型中站位和装备有实际影响，不代表数值已平衡。

当前不实现地图、成长、消耗品、挑战次数与真实人物内容。下一步直接试玩回答：站位选择是否清楚，自动技能是否能看懂，重复调整是否有趣；依据试玩再调整核心规则。
