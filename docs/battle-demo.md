# 战斗 Demo

这是用来验证战前布阵与自走棋自动战斗的临时原型，不连接正式存档。

当前为侧视 2D 版：我方从左侧、敌方从右侧接近，按空间距离移动、索敌与攻击。已有庭院、实验室和教室三张战斗背景，守护者与远射手使用绘制角色图集；其余同学和敌人仍使用 Kenney CC0 像素占位。待机、移动、攻击、弹道、伤害数字、治疗粒子、护盾轮廓与技能提示均已接入。占位素材来源与许可证位于 `assets/pixel/kenney/`，绘制资产状态见 `assets/art/asset_manifest.yaml`。

`pixel_battle.gd` 负责表现，继承 `battle_demo.gd` 的战斗规则与交互。战斗与正式冒险共用自动移动、索敌和射程规则。

在 PowerShell 7 中运行：

```powershell
pwsh.exe -File .\run-battle-demo.ps1
```

Godot 按 F5 后从模板主菜单的 Start 进入正式探索；独立实验室请使用上面的脚本，或打开 `scenes/battle_demo/battle_demo.tscn` 按 F6。实验室不连接正式存档。

- 战斗 Demo 与探索首战的我方棋盘为空；探索后续战斗自动沿用上一场已落定阵位。底部卡片 hover 轻微放大，未部署卡片点击后抬起，再次点击取消选中；悬停我方格即可预览，点击有效格立即部署或换人，不再二次确认。
- 按住卡片拖入我方格时显示预览，松手直接部署或换人。拖到场外、敌方或原格松手不修改阵容。
- 点击已部署单位本身弹出“交换 / 撤回”，点击战场空白或空的我方格会取消选择并收起按钮。点“交换”后，来源角色底盘发亮；点击空格立即换位、点击其他我方单位立即交换，点击来源自身则退出交换。点“撤回”直接回到卡牌区。点击已部署手牌可跳过菜单直接选目标并显示相同亮边。拖动已部署单位到空格直接换位、到我方单位直接交换、到卡牌区直接撤回；其他场外与敌方落点取消操作。最多部署四人，四人就绪后开战。Esc 或鼠标右键可在尚未选择目标时取消交换，暂停和失焦也会取消。
- 点击同学后，点击“装备”，分配唯一的篮球鞋（攻击间隔减少 25%）。
- 准备阶段点击敌阵按钮切换两种遭遇。
- 开战后全自动，每 3 次普攻附加一次技能；可以暂停或切换 1×／2×。
- 胜利后所有同学恢复完整状态；失败后点击重新编队，无限重试。
- 按 Esc / P、点击右上角“菜单”，或点击战斗中的“暂停战斗”打开暂停菜单。暂停会冻结战斗、计时、待机动作和特效。
- 暂停菜单可继续游戏、重新编队、返回主菜单、退出桌面游戏；返回主菜单与退出有确认提示，关闭窗口也走退出确认。Web 版隐藏关闭程序按钮。
- 确认框按 Esc 返回暂停菜单；菜单按钮支持 Tab／方向键焦点与 Enter 确认。当前 Demo 没有存档，返回主菜单后重新开始会使用初始阵容。

试验建议：将守护者部署在前排中间、冲刺手放前排右侧、远射手放后排左侧、应援者放后排中间，比较装备给不同同学的结果。

验证入口：`pwsh.exe -File .\run-battle-demo.ps1 -Smoke`。包含两组敌人、不同装备携带者、胜利恢复和 1×／2×结果一致性检查。

已使用本机 Godot 4.7.2 检查战斗与桌面画面。手机浏览器、Web 导出和跨平台中文字体尚未验证。当前以可玩规则为重点，尚未制作角色美术、音效、地图和成长。

## 自走棋战斗规则

- 保留六个战前布阵位；开战后双方在 7×7 逻辑场地自动行动。格距采用场景投影，射程按逻辑格的欧氏距离计算。
- 近战默认射程 1.45 格，远射手、应援者、发明家、晨光及对应远程敌人为 3.2 格；默认移速 2.4 格/秒。在人物资源中编辑 `attack_range` / `move_speed`。`attack_modes` 记录近战、远程或两者兼具的能力；旧资源值为 0 时按 `action_profile` 和射程推断。
- 射程内保留现有目标，没有有效目标时优先选择最近的范围内敌人；没有可攻击敌人时，用广度优先搜索寻找最近的可达攻击位置，自动绕开友军与敌军。相同距离按稳定的单位和方向顺序选择。
- 行走时保留起点和目的格的占位，不穿人、不交换穿越；受阻时等待并重算，死亡单位立即释放占位。移动结束后才能攻击，冷却在移动中恢复，但不会累积连发。
- 普攻与单体伤害技能受射程限制。后排优先按实时纵向位置判断；整排技能作用于当前目标横向带状范围（纵向差不超过半格）且在射程内的敌人。护盾作用于自身及约两格内友军；治疗与明确配置的全体技能保持全队作用域。
- 点击战场上的实际人物查看射程、移速；金线为所选人物的射程边界，虚线连接当前目标。战中点击只查看，不改变自动行动。
- 固定 0.05 秒模拟，暂停冻结位置与计时，1×／2×只改变推进速度；重新编队恢复初始位置。原有装备、技能计数、奖励和胜负结算继续生效。

这是自走棋战斗层的改造，尚未加入商店、购买合成、羁绊或经济系统。新的射程与范围会改变战斗平衡，需要后续实际游玩调优。

验证：使用 Godot `--headless --path . res://game/combat/auto_battle_check.tscn` 检查绕路、射程、死亡换目标、占位、暂停、复位与倍速；原 `--demo-smoke`、`--run-smoke` 覆盖布阵、装备和完整冒险。运行战斗场景并加 `-- --autobattle-capture` 可输出 1920×1080、2560×1440、1920×1200 的整备与战斗截图到 `.godot/`。

## 卡片部署与存档

本节记录 2026-09-12 用户提出的卡片部署交互及当前实现，适用于战斗 Demo 和正式冒险。它是玩法与实现说明，不是已批准或冻结的美术 Task Spec；下列实现参数也不代表独立的美术审批结果。

部署交互实现于 `scenes/battle_demo/deployment_panel.gd`。卡片来源为当前冒险 roster；Demo 使用初始四人。保留六个可部署格和四人出战规模，底部卡片替代战前日志；已部署卡片仍保留并标注状态，可重新选中换位或撤回。

未部署卡片点击后保持抬起，再次点击并松开取消选中；悬停有效格显示半透明预览。点击有效格立即部署或换人并保存，不显示确认按钮，也不需要第三次点击。

点击已部署单位本身仍打开“交换 / 撤回”操作菜单；菜单展开时点击战场空白或空的我方格，会清除角色选择并立即收起两个按钮，不修改阵容。点击底部手牌则直接进入选位状态，不必再点“交换”。进入交换选位后，来源角色显示金色发光底盘与亮边。已上阵手牌选择空格表示移动，选择其他我方单位表示两人换位；未上阵手牌选择占用格表示换人，原单位回到手牌。悬停预览目标位置，点击目标立即一次性更新阵容并保存。尚未选择目标时，点击来源自身、按 Esc 或鼠标右键均取消交换；点击菜单中的“撤回”则立即撤回。

按住卡片或已部署单位移动达到 8 个逻辑像素进入拖动模式，无需先点击操作菜单；同一张已选卡片开始拖动时不会触发取消选中。拖动落点规则：

| 来源 | 我方空格 | 其他我方单位 | 底部卡牌区 | 敌方、其他场外或原格 |
| --- | --- | --- | --- | --- |
| 未部署卡片 | 直接部署（仍受四人上限限制） | 直接换人，原单位回到手牌 | 取消 | 取消 |
| 已部署单位或其卡片 | 直接换位 | 直接交换 | 直接撤回 | 取消，保持原位 |

拖动过程中有效棋盘落点显示预览；交换时同时预览两名角色的新位置，临时隐藏原位置的实体显示以免重影，但松手前不修改阵容。已部署单位拖动时，卡牌区显示撤回提示；只有明确落入卡牌区才撤回，拖偏到其他场外位置不撤回。

表现复用现有角色 portrait、`resources/theme/theme-main.tres` 和 `scenes/ui/comic_ui.gd` 卡片形状。半透明预览为 35% 不透明度；未新增或替换正式美术，也不使用 Manifest 中的 concept 示例。Anchor 根节点与 HBoxContainer 卡片行沿用 1280×720 逻辑画布缩放，hover 动效读取 `data/visual/animation.json` 的 `micro` 时长。

Esc 优先取消尚未选择目标的部署手势；交换选位还可通过点击来源自身或鼠标右键取消。暂停和失焦也会取消，避免恢复时误落子。人数和操作说明放在状态文本中，按钮保持简洁。

点击有效格、拖拽有效落点与撤回会修改 formation 并保存；候选格、hover 和拖动过程为临时状态。存档允许 0～4 名部署角色，重复角色、非 roster 角色、超过四人仍拒绝。探索首战从空棋盘开始，后续遭遇沿用上场已落定阵位；同一场战斗暂停、重试、恢复存档也保留已落定位置。玩家仍可在每场战前调整。四人未部署齐时不允许开战，已有战斗结算人数规则保持不变。

战前底部持续显示最短操作提示：首战说明拖动卡片或依次点击卡片与我方空格，四人就绪后提示开战；后续战斗说明已沿用阵位并可调整。原规则每场至少需要四次拖动，或八次点选再开战，重复动作对五层短局没有新增决策价值；现规则只在首战要求完整部署，后续未调整时可直接开战，失败后的重新编队入口不变。

交互验证：Godot `--headless --path . res://scenes/battle_demo/deployment_check.tscn -- --deployment-check`。通过真实 Viewport 输入分发测试悬停预览、重复点击取消、点击立即部署／换人／换位、操作菜单及空白收起、交换来源标识、Esc／自身格／右键取消选位、直接拖动交换／换位／撤回、非法落点、移动阈值、人数上限、失焦、暂停、部分部署读档、整场战斗与下场沿用。将参数改为 `--deployment-capture` 并移除 `--headless`，可生成 1920×1080、2560×1440、1920×1200 的空棋盘、悬停预览、点击后阵容、拖动预览、已部署、操作菜单、空白收起、交换来源发光和交换结果截图；只复核菜单展开／收起画面时，可在图形模式使用 `--deployment-check --deployment-dismiss-capture`。`--run-capture` 另生成探索首战提示与后续沿用截图。

## 行动时序框架（2026-09-13）

### 左右布阵与对象详情

站位显示映射将后排向内收，并为三行角色保留间距；最外侧寻路格压缩到安全显示边界。背景使用地点配置的归一化 `battle_crop`（本组三图为 0.085, 0.123, 0.83, 0.833），裁去边缘摆设，让全部部署位落在连续地面上；源图像素保持不变。

三张战斗背景通过 `CampusLocation.battle_background` 关联：校门、篮球场和教学区沿用日间庭院，实验室使用夜间电子实验室，异变教室与终点使用异常教室。按现有地点 ID 查视觉资源，不把纹理写入存档快照；Demo 按敌阵选择庭院 / 教室。原始图片与完整生成提示词存放于 `assets/art/backgrounds/battle_*/`，Manifest 为 review，待人工视觉 QA。背景单独使用线性过滤，角色帧及棋盘逻辑保持独立。

验证入口：`res://scenes/battle_demo/battle_ui_check.tscn -- --deployment-check`。检查角色详情、装备弹窗空白关闭、装备／转移成功后自动关闭、归属与战斗只读限制。增加 `--battle-ui-capture` 并使用图形模式，可导出三张背景在 1920×1080、2560×1440、1920×1200 的实机截图，以及角色详情、背包和弹窗关闭后的画面；只复核装备弹窗开／关画面时，可使用 `--deployment-check --battle-equipment-capture`。该入口使用独立测试存档。

战斗表现使用 `battle_board.gd` 旋转原逻辑坐标：我方在左、敌方在右，前后排关系、六个阵容槽位和距离结算保持不变。部署区之间预留中间交战空间。右侧不再常驻人物手册；悬停角色显示生命、攻击与护盾，点击固定技能、属性与装备详情，优先放在中间空白处，靠近边缘时限制在战场内。点击空白或 Esc 收起；浮层不会触发布阵，原卡牌拖放、交换与撤回继续使用原流程。

装备栏使用与队伍界面、图鉴一致的 `object_icon.gd`。点击槽位打开背包，显示装备描述、当前携带者和转移结果；点击内容区外的空白会关闭装备弹窗，“装备 / 转移 / 卸下”成功后也会自动关闭。“装备 / 转移 / 卸下”才更改归属。每人一件，替换后旧装备回到背包，使用已有 inventory 与存档机制。战斗中允许查看，禁止交换。

队伍面板内的装备、阵型和技能详情均可用关闭图标、Esc／P 或点击内容区外的空白遮罩关闭；内容区点击保持弹窗并拦截底层操作。后续新增覆盖式对象详情沿用同一关闭规则。

后续对象交互默认沿用“图标缩略展示 → 悬停摘要 → 点击详情 / 操作”的实践，详情和解释放入浮层或展开面板，按钮使用简短动作名。不得为相同物品建立多套图标。

Demo 与正式冒险共用 `game/combat/battle_simulation.gd`，固定 0.05 秒推进。`request_action(actor_id, target_id, kind)` 是统一入口，当前仅接受 `attack`，忙碌、死亡、冷却或射程不满足时拒绝；未来手动技能和物品可扩展明确的请求类型。

人物可选 `action_profile`，缺省前摇 0.20 秒、后摇 0.25 秒、弹速 8 格/秒；射程超过 1.5 格默认弹道，也可显式配置 melee/projectile。动作时长按比例适配攻击间隔，装备将间隔压到 0.1 秒以下时也保持正时长；实际出手截止点量化到 0.05 秒模拟步，收招完成后不额外插入空白步。逻辑位置在出招期间不动。前摇结束时检查目标与射程，成功出手才累计普攻次数并附加技能。弹道抵达时才结算伤害，已发射弹道不随施法者死亡取消，目标死亡则消散。到期效果先收集，支援先于伤害结算，允许双方同时退场。

2026-09-22 结算精确性补充：每步先统一移动，再处理所有前摇释放和追踪弹道；支援与命中结算完成后取消死亡单位动作、请求下一动作。普通单体技能沿用已锁定主目标；低血量目标按浮点生命比例比较，平手按距离与稳定 ID。非零伤害按防御减免四舍五入后至少1点，0伤害不制造扣血。对同一目标的当批伤害一起扣除护盾和生命，实际伤害／格挡统计按各命中减免后伤害的比例分摊，避免数组顺序影响击杀贡献。

护盾总上限144，记录来源与失效时间，先消耗较早失效的护盾；同到期时间按来源稳定排序。只清除指定来源时保留其余层，旧代码直接改写护盾数值仍有兼容同步。派生规则在整批结算后读取 `valid / actual / blocked`，半血反应不复活同批死亡者。验证入口新增 `res://game/combat/accuracy_check.tscn`。

表现事件包含动作编号、单位编号、模拟时间、逻辑位置与结果快照，不携带可变单位引用。一方退场后停止新行动，等待在途弹道完成再判断胜负；双方退场视为失败。画面保留至少 0.65 秒收尾（剩余死亡片段更长时等待播完），再恢复胜利方并进入结果；headless 不等待画面收尾。90 秒上限停止新行动，仍处理已发射弹道。

验证入口：Godot `--headless --path . res://game/combat/action_check.tscn`。覆盖前摇、射程落空、死亡取消、弹道延迟与消散、最后弹道导致双方退场、同时命中、支援优先、事件快照、高攻速和复位。原有寻路与整场冒险验证继续适用。

## 三战试炼：羁绊与系统破解

### 四色代码与配方破解

当前玩家入口改用 `code_trial_simulation.gd`。旧百分条模拟仅保留为兼容回归入口，以下为实际规则：

| 代码 | 产出人物 | 识别符号 |
| --- | --- | --- |
| 红色·指令 | 射手、突击手 | `>` |
| 蓝色·数据 | 分析员 | `{}` |
| 绿色·协议 | 治疗员 | `↔` |
| 紫色·权限 | 守卫、发明家 | `#` |

- 每个人每3次有效普攻动作产出1块自身代码，自动收集；每色上限6，每场清零。同一动作多目标不重复计数；护盾吸收算命中，落空、零效果、死靶不算。颜色同时配名称和符号。
- 分析员技能标记4秒漏洞，其他队友普攻验证获得1块标记者颜色代码；制造者不能自验。协同验证奖励允许两名不同队友分别验证。发明家技能额外产出1块权限；解析羁绊成员首次有效技能各产出1块自身代码。
- 每场战前携带两种不同程序，可调整；界面提示队伍缺少的产色能力。点击「破解」或Esc打开终端，暂停战斗与动画，继续后恢复；不自动打断战斗。程序共享3秒模拟时间冷却。

| 程序 | 消耗 | 效果 |
| --- | --- | --- |
| 断链 | 指令2＋权限1 | 清除敌方维护来源护盾，跳过下一次维护脉冲 |
| 重定向 | 数据2＋协议1 | 下一次维护脉冲保护我方最低生命比例者 |
| 热修复 | 协议2＋数据1 | 恢复至多两名最低生命比例伤员各25%最大生命 |
| 提权 | 权限2＋数据2 | 本场永久接管维护，后续脉冲保护我方最低生命比例者 |

待执行的单次维护命令不可覆盖；提权每场一次，提权后不能再执行维护类程序。全员满血时拒绝热修复。所有失败操作不扣资源；未破解也可直接击败敌人获胜。创客社只在本场首次执行程序时触发攻速提升。

两槽道具每局三战开始时各1件，跨战斗消耗：代码补给生成3块指定颜色；转码器消耗2块源颜色生成2块不同目标颜色。界面预览使用后数量。超过缓存上限、材料不足或同色转换直接拒绝，不部分扣费或吞掉溢出。

道具消耗先留在本场模拟中，胜利保存时才提交剩余库存；失败或中断恢复战前库存，胜利保存失败回滚并保留战报重试。开新一局恢复两件道具；代码块、程序冷却及维护指令不跨战保存。v3存档保存程序装配和道具库存，旧档迁移给予默认程序与初始道具，不改原v1/v2文件。

破解终端以代码槽呈现库存及配方：带颜色与符号的实心槽表示已有代码，斜线空槽表示缺口；配方槽按实际成本生成，不代表额外预留或扣费。两列程序卡显示各自成本、效果与可用状态，道具卡预览生成类型及块数，并保留使用后库存提示。战斗HUD与终端共用图形组件，所有数值读取当前模拟；暂停时仍可操作程序／道具，继续后恢复战斗。
