# 战斗 Demo

战前布阵与自走棋战斗复用原校园流程的界面和模拟。`run-battle-demo.ps1` 现在统一选择 Debug / Release 并进入校园流程；独立 `battle_demo.tscn` 保留为自动化与美术试验夹具，不连接正式存档。

当前为侧视 2D 版：我方从左侧、敌方从右侧接近，按空间距离移动、索敌与攻击。已有庭院、实验室和教室三张战斗背景，五名我方角色使用正式整身动画包；未接入绘制资产的角色仍使用 Kenney CC0 像素占位。待机、移动、攻击、弹道、伤害数字、治疗粒子、护盾轮廓与技能提示均已接入。占位素材来源与许可证位于 `assets/pixel/kenney/`，正式绘制资产状态见 `assets/art/asset_manifest.yaml`；最新五人正式包均为 asset_002。

`pixel_battle.gd` 负责表现，继承 `battle_demo.gd` 的战斗规则与交互。战斗与正式冒险共用自动移动、索敌和射程规则。

在 PowerShell 7 中运行：

```powershell
pwsh.exe -File .\run-battle-demo.ps1
```

不带参数时显示 **Debug / Release** 启动菜单，回车默认 Debug，输入 `0` 退出。也可直接指定模式：

```powershell
pwsh.exe -NoProfile -File .\run-battle-demo.ps1 -Mode Debug
pwsh.exe -NoProfile -File .\run-battle-demo.ps1 -Mode Release
```

| 模式 | 入口与存档 | 动画及调试能力 |
| --- | --- | --- |
| `Debug` | 原校园战斗入口，四人自动部署并开战；临时 `.godot/debug-battle-preview.json` | 最新五人正式资源；首战部署守护者/远射手/冲刺手/支援者；F8 / 右上角“调试”打开游戏内面板 |
| `Release` | 原校园流程，正常 `campus_progress.json` | 使用正式角色资源，关闭校园调试面板 |

Debug 每次启动直接进入新的序章遭遇战，无需完成基地任务、解锁地图或手动布阵；复用原校园遭遇、战斗、战报和存档编解码，只写临时预览档，正式档与原校园 Debug 进度均保留。战斗难度在游戏内选择：**F8 / 调试 → 战斗难度 → 应用重开**，保留当前敌阵与构筑，恢复满血后立即开战。操作边界见[Debug 模式](debug-mode.md)。这里的 Release 指本地正常试玩模式；发行包仍走现有导出流程。

Debug／Release 默认 `-Animations Formal`，五人均加载稳定 `assets/art/characters/<角色>/battle_animation.tres`。初始四人阵容不含发明家；完整五人覆盖使用两组合法阵容，来源与正式批准见[人物任务](art/tasks/m1-player-cast-animation.md)。`Current` 保留为兼容参数，在 `demo_options.gd` 指向同一正式包，不依赖已删除本地候选。

`-Size` 可选 `1920x1080`（默认）、`2560x1440`、`1920x1200`，本次启动按窗口模式应用，不修改全局显示设置。`-Mode Debug -Smoke` 直接检查实际启动的战斗与游戏内调难度，完成标记 `DEBUG_BATTLE_CHECK`；`-Mode Release -Smoke` 检查调试能力关闭。显式模式下的 `-Capture` 分别检查启动战斗和正常主线集成画面，均使用独立测试档后自动退出。普通启动不会自动退出。

### 固定战斗试验

固定难度参数只作为显式试验入口保留，不出现在启动菜单中，也不能和 `-Mode` 混用：

```powershell
pwsh.exe -NoProfile -File .\run-battle-demo.ps1 -Difficulty Hard
```

将 `Hard` 换成 `Easy` 或 `Normal` 可运行其他样本；三档自动部署满血四人并开战，`-Difficulty Manual` 保留空棋盘手动部署。战中可暂停、调整倍速和重试；点击“返回整备”后可“切换难度”再开战，手动夹具仍“切换敌阵”。

| 选项 | 战斗样本 | 用途 |
| --- | --- | --- |
| `Easy` / 简单 | 巡逻敌阵，降低敌方生命与攻击 | 观察移动、普攻、施法与胜利收尾 |
| `Normal` / 普通 | 巡逻敌阵，原始属性 | 对照完整常规战斗 |
| `Hard` / 困难 | 终点敌阵，增加敌方生命 | 三名角色真实触发受击、濒危和退场 |

这些是开发演示样本，不定义正式校园的难度档位。属性配置只维护于 `game/combat/demo_battle_presets.gd`，复用原敌人资源、战斗模拟和界面；重试不会重复叠加数值，也不写入存档。

显式简单／普通／困难样本默认使用当前三人候选，手动样本默认正式资源。可指定 `-Animations Formal`：

```powershell
pwsh.exe -NoProfile -File .\run-battle-demo.ps1 -Difficulty Hard -Animations Formal
```

未指定 `-Mode` 的 `-Capture -CaptureAt 10.6` 保留旧单场 Viewport 截图到 `.godot/battle_demo_combat.png` 后退出；未指定 `-Difficulty` 时使用手动正式资源夹具。`CaptureAt` 只控制该单场截图，不控制模式集成检查。

Godot 按 F5 后从模板主菜单的 Start 进入正常校园；独立实验室用显式 `-Difficulty` 参数，或打开 `scenes/battle_demo/battle_demo.tscn` 按 F6。实验室不连接正式存档。

- 手动战斗 Demo 与探索首战的我方棋盘为空；探索后续战斗自动沿用上一场已落定阵位。底部卡片 hover 轻微放大，未部署卡片点击后抬起，再次点击取消选中；悬停我方格即可预览，点击有效格立即部署或换人，不再二次确认。
- 按住卡片拖入我方格时显示预览，松手直接部署或换人。拖到场外、敌方或原格松手不修改阵容。
- 点击已部署单位本身弹出“交换 / 撤回”，点击战场空白或空的我方格会取消选择并收起按钮。点“交换”后，来源角色底盘发亮；点击空格立即换位、点击其他我方单位立即交换，点击来源自身则退出交换。点“撤回”直接回到卡牌区。点击已部署手牌可跳过菜单直接选目标并显示相同亮边。拖动已部署单位到空格直接换位、到我方单位直接交换、到卡牌区直接撤回；其他场外与敌方落点取消操作。最多部署四人，四人就绪后开战。Esc 或鼠标右键可在尚未选择目标时取消交换，暂停和失焦也会取消。
- 点击同学后，点击“装备”，分配唯一的篮球鞋（攻击间隔减少 25%）。
- 手动模式准备阶段点击“切换敌阵”切换两种遭遇；难度样本使用“切换难度”。
- 开战后全自动，每 3 次普攻附加一次技能；可以暂停或切换 1×／2×。
- 胜利后所有同学恢复完整状态；失败后点击重新编队，无限重试。
- 按 Esc / P、点击右上角“菜单”，或点击战斗中的“暂停战斗”打开暂停菜单。暂停会冻结战斗、计时、待机动作和特效。
- 暂停菜单可继续游戏、重新编队、返回主菜单、退出桌面游戏；返回主菜单与退出有确认提示，关闭窗口也走退出确认。Web 版隐藏关闭程序按钮。
- 确认框按 Esc 返回暂停菜单；菜单按钮支持 Tab／方向键焦点与 Enter 确认。当前 Demo 没有存档，返回主菜单后重新开始会使用初始阵容。

试验建议：将守护者部署在前排中间、冲刺手放前排右侧、远射手放后排左侧、应援者放后排中间，比较装备给不同同学的结果。

验证入口：`pwsh.exe -File .\run-battle-demo.ps1 -Smoke`。不指定难度的检查默认使用正式资产，保留两组敌人、不同装备携带者、胜利恢复和 1×／2×结果一致性检查。指定 `-Difficulty Easy/Normal/Hard -Smoke` 则检查真实战斗、动画选择、暂停、重试数值和难度切换；困难当前动画检查还要求三名角色各自出现全部七个状态。原 `-CodeCheck` / `-CodeCapture` 保留主线集成检查入口，不接受难度与动画覆盖。

已使用本机 Godot 4.7.2 检查战斗与桌面画面。本次难度启动选项只验证 Windows 桌面；手机、Web 导出和跨平台中文字体不在该检查范围。完整美术收尾和真人平衡体验仍待验证。

## 自走棋战斗规则

- 保留六个战前布阵位；开战后双方在 7×7 逻辑场地自动行动。格距采用场景投影，射程按逻辑格的欧氏距离计算。
- 近战默认射程 1.45 格，远射手、应援者、发明家、晨光及对应远程敌人为 3.2 格；默认移速 2.4 格/秒。在人物资源中编辑 `attack_range` / `move_speed`。`attack_modes` 记录近战、远程或两者兼具的能力；旧资源值为 0 时按 `action_profile` 和射程推断。
- 射程内保留现有目标，没有有效目标时优先选择最近的范围内敌人；没有可攻击敌人时，用广度优先搜索寻找最近的可达攻击位置，自动绕开友军与敌军。相同距离按稳定的单位和方向顺序选择。
- 行走时保留起点和目的格的占位，不穿人、不交换穿越；受阻时等待并重算，死亡单位立即释放占位。移动结束后才能攻击，冷却在移动中恢复，但不会累积连发。
- 普攻与单体伤害技能受射程限制。后排优先按实时纵向位置判断；整排技能作用于当前目标横向带状范围（纵向差不超过半格）且在射程内的敌人。护盾作用于自身及约两格内友军；治疗与明确配置的全体技能保持全队作用域。
- 点击战场上的实际人物查看射程、移速；青色地面投影为所选人物的射程，虚线连接当前目标。战中点击只查看，不改变自动行动。B 方案的场地边界常驻，切角部署垫仅在整备时显示；等间隔场地投影与逻辑距离一致，超出场地的射程填充裁切，弧线自然截断，不将圆周点夹成折角。

### 破解演出

在平铺破解图标成功执行后生成演出，鼠标离开悬停区域恢复战斗并播放约 2.2 秒的分层演出：代码汇聚、程序环、释放光芒、扩散波、渐隐。程序共用视觉节奏，以颜色和独立图标区分。只有立即受影响的角色获得连接光束；重定向的提示明确说明等待下次维护。HUD“简化特效”可关闭移动光束与粒子，仅保留静态程序提示；设置在当前场景内保留。暂停冻结演出，不改变战斗判定与模拟时间。

验证入口：scenes/battle_demo/battlefield_visual_check.tscn -- --capture 和 hack_feedback_check.tscn -- --capture --frames。二者均实例化原 expedition.tscn，不提供平行战斗玩法入口。检查项和已知边界见 UI-02 / CORE-05。
- 固定 0.05 秒模拟，暂停冻结位置与计时，1×／2×只改变推进速度；重新编队恢复初始位置。原有装备、技能计数、奖励和胜负结算继续生效。

这是自走棋战斗层的改造，尚未加入商店、购买合成、羁绊或经济系统。新的射程与范围会改变战斗平衡，需要后续实际游玩调优。

验证：使用 Godot `--headless --path . res://game/combat/auto_battle_check.tscn` 检查绕路、射程、死亡换目标、占位、暂停、复位与倍速；原 `--demo-smoke`、`--run-smoke` 覆盖布阵、装备和完整冒险。运行战斗场景并加 `-- --autobattle-capture` 可输出 1920×1080、2560×1440、1920×1200 的整备与战斗截图到 `.godot/`。

## 卡片部署与存档

本节记录 2026-09-12 用户提出的卡片部署交互及当前实现，适用于战斗 Demo 和正式冒险。它是玩法与实现说明，不是已批准或冻结的美术 Task Spec；下列实现参数也不代表独立的美术审批结果。

部署交互实现于 `scenes/battle_demo/deployment_panel.gd`。卡片来源为当前冒险 roster；Demo 使用初始四人。保留六个可部署格和四人出战规模，底部卡片替代战前日志；已部署卡片仍保留并标注状态，可重新选中换位或撤回。

未部署卡片点击后保持抬起，再次点击并松开取消选中；悬停有效格显示半透明预览。点击有效格立即部署或换人并保存，不显示确认按钮，也不需要第三次点击。

点击已部署单位本身仍打开“交换 / 撤回”操作菜单；菜单展开时点击战场空白或空的我方格，会清除角色选择并立即收起两个按钮，不修改阵容。点击底部手牌则直接进入选位状态，不必再点“交换”。进入交换选位后，来源角色显示金色发光底盘与亮边。已上阵手牌选择空格表示移动，选择其他我方单位表示两人换位；未上阵手牌选择占用格表示换人，原单位回到手牌。悬停预览目标位置，点击目标立即一次性更新阵容并保存。尚未选择目标时，点击来源自身、按 Esc 或鼠标右键均取消交换；点击菜单中的“撤回”则立即撤回。

按住卡片或已部署单位移动达到 8 个逻辑像素进入拖动模式，无需先点击操作菜单；同一张已选卡片开始拖动时不会触发取消选中。拖动落点规则：

| 来源 | 我方空格 | 其他我方单位 | 底部卡牌区 | 敌方、其他场外或原格 |
| --- | --- | --- | --- | --- |
| 未部署卡片 | 直接部署（仍受四人上限限制） | 直接换人，原单位回到手牌 | 取消 | 取消 |
| 已部署单位或其卡片 | 直接换位 | 直接交换 | 直接撤回 | 取消，保持原位 |

拖动过程中有效棋盘落点显示预览；交换时同时预览两名角色的新位置，临时隐藏原位置的实体显示以免重影，但松手前不修改阵容。已部署单位拖动时，卡牌区显示撤回提示；只有明确落入卡牌区才撤回，拖偏到其他场外位置不撤回。

表现复用现有角色 portrait、`resources/theme/theme-main.tres` 和 `scenes/ui/comic_ui.gd` 卡片形状。半透明预览为 35% 不透明度；未新增或替换正式美术，也不使用 Manifest 中的 concept 示例。Anchor 根节点与 HBoxContainer 卡片行沿用 1280×720 逻辑画布缩放，hover 动效读取 `data/visual/animation.json` 的 `micro` 时长。

Esc 优先取消尚未选择目标的部署手势；交换选位还可通过点击来源自身或鼠标右键取消。暂停和失焦也会取消，避免恢复时误落子。人数和操作说明放在状态文本中，按钮保持简洁。

点击有效格、拖拽有效落点与撤回会修改 formation 并保存；候选格、hover 和拖动过程为临时状态。存档允许 0～4 名部署角色，重复角色、非 roster 角色、超过四人仍拒绝。探索首战从空棋盘开始，后续遭遇沿用上场已落定阵位；同一场战斗暂停、重试、恢复存档也保留已落定位置。玩家仍可在每场战前调整。四人未部署齐时不允许开战，已有战斗结算人数规则保持不变。

战前底部持续显示最短操作提示：首战说明拖动卡片或依次点击卡片与我方空格，四人就绪后提示开战；后续战斗说明已沿用阵位并可调整。原规则每场至少需要四次拖动，或八次点选再开战，重复动作对五层短局没有新增决策价值；现规则只在首战要求完整部署，后续未调整时可直接开战，失败后的重新编队入口不变。

交互验证：Godot `--headless --path . res://scenes/battle_demo/deployment_check.tscn -- --deployment-check`。通过真实 Viewport 输入分发测试悬停预览、重复点击取消、点击立即部署／换人／换位、操作菜单及空白收起、交换来源标识、Esc／自身格／右键取消选位、直接拖动交换／换位／撤回、非法落点、移动阈值、人数上限、失焦、暂停、部分部署读档、整场战斗与下场沿用。将参数改为 `--deployment-capture` 并移除 `--headless`，可生成 1920×1080、2560×1440、1920×1200 的空棋盘、悬停预览、点击后阵容、拖动预览、已部署、操作菜单、空白收起、交换来源发光和交换结果截图；只复核菜单展开／收起画面时，可在图形模式使用 `--deployment-check --deployment-dismiss-capture`。`--run-capture` 另生成探索首战提示与后续沿用截图。

## 行动时序框架（2026-09-13）

### 左右布阵与对象详情

站位显示映射将后排向内收，并为三行角色保留间距；最外侧寻路格压缩到安全显示边界。背景使用地点配置的归一化 `battle_crop`（本组三图为 0.085, 0.123, 0.83, 0.833），裁去边缘摆设，让全部部署位落在连续地面上；源图像素保持不变。

### 基准与结算

四人满血，无装备、无局外属性，代码和吸收余量每场清零。普通战目标25～40秒，Boss30～45秒；正常承压首个核心程序8～12秒，30秒通常总计2～3次程序。低压护盾队允许延后至12～16秒，接近30秒追加救急可能达4次，需评审而非强行禁用。道具可突破首发目标，另行测试。

沿用原公式：伤害=round(原始伤害×100/(100+防御))，正伤害至少1；普攻、技能、追击、爆炸均先减防再扣盾再扣血，无暴击/随机浮动。技能在每N次成功普攻出手时附加，不替代普攻；追击、技能、爆炸不累积普攻计数。前摇0.20秒、后摇0.25秒、弹速8格/秒；下表周期为连续攻击名义值，不含接敌与弹道延迟。移速统一2.4格/秒，半径按逻辑坐标欧氏距离、包含边界。射程外不普攻，普攻选最近目标。

保留同批伤害、在途弹道、双方阵亡视为失败和90秒上限。平手按稳定ID。普通盾同来源刷新为旧剩余与新值较大者并刷新时长，不叠加；各来源共用144总上限，只计算实际增加和吸收。

### 漏洞链与程序

漏洞6秒→队友有效普攻验证→已确认8秒→玩家追踪破解→暴露5秒。无漏洞羁绊时仍可验证变已确认，但无基础追击和额外蓝。每次分析在非暴露目标上放置一份待验证机会，持续6秒、不可叠加；已确认期间的新机会不清除已确认。另一名友军普攻消耗该机会验证，并从本次起刷新已确认8秒；分析本身不延长已确认。暴露期间分析只伤害、不新增机会。暴露结束清空，下次分析重新挂。标记者死亡不取消已确认。

暴露期间，每名友军第一次有效普攻命中该敌人额外追击1.0×自身攻击，最多四次；新追击要求攻击者仍存活。追击为即时伤害，不产码、不触发技能/验证/追击，不转移至其他目标。

仍装两个程序。漏洞队带追踪+修复，护盾队带反冲+修复，混合队可带两个核心程序。总施放次数包括备用程序。

反冲边界：每人一层，优先于普通盾吸收；施放时预留30容量，必要时裁去最晚到期普通盾，裁去部分不产码，预览须显示替换量。只反冲盾爆炸，普通盾不爆；到期与击破同一步去重。致死命中击破反冲盾仍在死亡位置爆一次，不能复活施法者；战斗结束清理和驱散不爆炸。冷却长于盾持续时间。每枚盾每敌人只命中一次，四人同击一敌上限120原始伤害，后排远离敌人时可能只获防护而无伤害。

反冲吸收也产紫。四人一轮最多吸收120，即1.5紫长期当量，小于成本2；有旧余量时单次可能跳出2紫。N轮最多由这些盾贡献floor((旧余量+120N)/80)紫，旧余量<80，不能持续自给2N紫，且仍需绿码与外部普通盾。强化首轮不增加特殊盾量、不降80阈值。

### 两条流程纸面核算

漏洞队：守护者+冲刺手前排、分析员+远射手后排，只激活漏洞研究。连续攻击假设下，分析约4.8秒普攻产蓝1并挂漏洞，随后验证蓝+1，约9.6秒普攻再产蓝1；红约3.75～4.5秒已有，因此首发围绕第二轮分析。一次四人完整暴露额外原始伤害45+22+22+34+30=153，对防御20约128；不包含基础普攻/验证。30秒普攻理论蓝6，验证3～5次再得3～5，但接敌、死亡、冷却、目标有效性都会减少实际施放。

护盾队：守护者+冲刺手前排、发明家+应援者后排，只激活容错工程。开场40、首轮并肩96、备份64，共200名义盾容量；重叠和空盾会损失，不能等同200吸收。首发需真正吸收160且有绿1，应援普攻约5.4秒产首绿。能否8～12秒完成取决于敌人承压；释放后120特殊盾全吃满仍需额外40普通盾吸收才补足下一轮160阈值，且等10秒冷却。后排盾常到期，实际返还更低。

混合队：守护者、应援者、分析员、远射手，两羁绊+两核心程序。牺牲冲刺手输出和清场换双解法；若在时间、伤亡、资源三方面全面优于专精队，应先调混搭资源效率。

### v0.2设计依据：用资源曲线约束战斗强度

本轮采用card-game的费用曲线、组合可靠性与触发边界，采用roguelike的局内成长、奖励分布与资源机会成本。没有移植抽牌、牌库、地牢回合或永久死亡。继续遵循主线胜利全恢复、失败可重试；消耗品的意义是省下以后应急机会，不以永久死亡恐吓玩家。以下数字皆为设计模型，不是实机统计。

**玩家应有的三种决策：**
1. 战前选主输出链、承伤结构及两个程序；不用所有颜色都齐。
2. 战中在“现在拿收益”和“留给3秒后的危险”之间选择；允许暂停查看，不要求反应速度。
3. 战后在提高循环可靠性、提高收益和补救短板中选一项；稀有不等于全方面更强。

#### 收入账本：先算总生成，再算存量

理想基准定义为第一个普攻命中发生于各自攻击间隔，之后连续命中；实际原模拟器未承诺这种开场。下表忽略死亡、移动、攻击中断、资源上限和支出，只用于核对产出潜力，不能直接当HUD余额。

|时间|漏洞队红（远射+冲刺）|分析员普攻蓝|护盾队红（冲刺）|应援普攻绿|
|---|---:|---:|---:|---:|
|5秒|2|1|1|0|
|10秒|4|2|2|1|
|20秒|9|4|5|3|
|30秒|14|6|8|5|

每个角色普攻代码= floor(时间/(间隔×3))；漏洞额外蓝=有效验证次数，暴露期不新增待验证机会。护盾紫=floor(实际累计吸收/80)。库存=min(6,上次库存+本次产出)，然后按每次实际施放扣除；溢出不能事后补领。

漏洞链示例账本（只演示条件成立时的资源，不是仿真）：4.8秒分析普攻蓝1，5.0秒验证蓝+1，9.6秒普攻蓝+1并放新机会，9.8秒验证蓝+1；10秒消耗蓝3红1，余蓝1。14.4秒普攻蓝+1但处于暴露，不挂新机会；19.2秒普攻蓝+1、新分析，19.4秒验证蓝+1；20秒再次支付蓝3，余蓝1。只要三人能接触目标，自动链在玩家不操作时也能持续工作；第三次是否在30秒合法取决于后续验证与目标是否存活。

护盾压力采用**外部普通盾实际吸收率**作为输入，不能拿敌人面板DPS直接替代。低/正常/高分别以10/16/24点每秒做敏感性情景，首160吸收最早分别16/10/6.67秒；这是假设从开战均匀吸收的简化下界，真实供盾是5.4秒一批，空窗和到期会延迟。高压能较早出程序属于承伤回报，不通过硬开场锁惩罚。

|截至时间|低压外部吸收/紫总产量|正常外部吸收/紫总产量|高压外部吸收/紫总产量|
|---|---|---|---|
|10秒|100 / 1|160 / 2|200 / 2（受供盾上界限制）|
|20秒|200 / 2|320 / 4|480 / 6|
|30秒|300 / 3|480 / 6|720 / 9|

此表已按普通供盾总量截断，仍未计护盾到期/刷新损失，未加特殊盾回流、不扣支出、不处理库存容量。高压理论240吸收在10秒没有足够供盾，所以表中只列200/2紫。必须同时检查**供给上界**。供盾函数（不含应援满血盾）为40+160×floor(t/5.4)，实际吸收≤此量，且可能因刷新、到期更低。高压情景不能拿240伪造10秒第三紫；这正是同时检查收入与供给的原因。

纸面首发检查：首轮200全部被有效利用时，需求160对应80%利用率。若利用率仅60%，首轮只能120，必须等约10.8秒下一批普通盾。开场20盾持续5秒，首技能约5.4秒，两批之间有短空窗，不能默认开场盾还存在。若正常敌阵反复到16秒仍没160吸收，应先检查盾是否给错人/在后排浪费，不先降低全局阈值。

|程序|保守情景|良好情景|成本中真正重要的限制|
|---|---|---|---|
|追踪破解|仅远射和分析各追击一次：45+34+22=101原始伤害|四人全触发153|必须有已确认、队友能接触、蓝3与10秒冷却|
|反冲护盾|两前排吸满60，两次爆炸各打1人：60吸收+60原始伤害，0.75紫当量|四盾吸满120，合计6次敌人命中：120吸收+180原始伤害，1.5紫当量|承伤压力、半径、紫2绿1与10秒冷却|

防御20时分别对每个伤害事件四舍五入；153/1.2≈127.5仅是合计近似，不能代替逐事件取整。多敌同时被四盾炸到可以超过180总伤害，最大为120×范围内敌人数（四人全部覆盖）；不要把每敌上限120误写为全战场上限。

这些收益不能简单相加为“战力分”：护盾只有被打才有效，治疗只有缺血才有效；对多目标伤害未必及时减少敌人行动。护盾队用持续防护换更慢击杀；漏洞队用集中伤害减少未来承伤。反冲不能同时按“120额外承伤收益”和“本来普通盾也会吸收的120”双算；需记录有/无程序两条成对战斗的实际HP差。

反冲盾替换普通盾时，新增净盾可能为0，但仍提供爆炸；预览显示特殊盾30、被替换普通盾量和预计净盾，不能只显示“+30”。这项复杂性先保留为边界，若实测替换频繁（超过10%施放），优先重审总盾上限与供盾重叠，而不是再加隐藏例外。

### 成型与奖励预算：随机的是变强方向，不是能否启动

本轮为主线数值验证配置，使用现有部署/招募/战利品页面，不增加平行入口。正式人物事件与永久解锁遵守game-design.md；以下“保证”需要接入相应角色内容事件，不能直接重写老存档或绕过剧情永久授予。

1. 第一次需要选择流派前，保证本局能取得对应最小组合：漏洞=分析员+任意一名其他漏洞标签；护盾=守护者+应援者。首次选择哪条链，就保证获得该核心程序和热修复，不将必需程序放在稀有随机池。
2. 两套完整四人标准队用于开发/试玩配置。正式冒险不要求新档立即拥有全部七人；在首次完整流派教学结束前，让对应人物通过现有招募/人物事件成为本局候选。尚未具备这些内容时不能声称新档已支持双流派。
3. 第一次关键强化之前链必须能自行启动。发明家提高供盾覆盖而不是首发的唯一门票；晨读提高蓝供给而不是替代分析的启动器。
4. 第一场验证基础链；第一奖励强化可靠性；第二场检验应对预警；第二奖励选择爆发或生存；第三场组合检验。三场只是选取主线节点，不要求主线总长度等于三场。
5. 战后全恢复，因此短期HP不是跨战斗稀缺资源；跨战斗稀缺的是强化机会、装备槽、候补选择和消耗品。无需照搬roguelike的永久死亡或食物消耗。

**每次战利品展示三个不同选项，选择一个：**
- A槽“已成型链强化”：从合法且未领取的对应流派项按权重取一；无对应项时转通用。
- B槽“通用/补短板”：训练、应急备份、代码补给一件，按权重取一。
- C槽“换法/其他方向”：从剩余合法项取一；第二次奖励前强制用此槽至少展示一次尚未拥有的适配候补人物招募。接受与否由玩家决定，不取走A槽。
- 候选先过滤人物、程序、羁绊、已领取与装备适用性，再按槽位顺序加权抽样且不重复。显示结果写入现有检查点，失败重试、重开面板不重抽。
- 可同时拥有两链时，A槽两类各50%，再在类内按权重抽；不直接把池合起来，让条目更多的一链占便宜。
- 第一次奖励排除协议缓冲和贯穿射击，避免教学阶段过多范围/时序改变；第二次起开放。

权重是相对权重，不是百分比；如漏洞A第一次仅镜片/协同合法，则各1/2，第二次全部合法则3/8、3/8、2/8。领奖前拥有分析员才允许协同，拥有远射才允许贯穿，装备类必须至少有一名合法携带者。不得为凑三选一生成不可用专属。池耗尽时C/B可补转码器一件，仍同页不重复；再不足时宁可显示两个合法选项，不增加一套无边界填充奖励。

本轮三战样本有两次间场关键强化选择，不代表整段M1只有两次奖励；正式奖励频次沿用主线。各局内战斗强化每局限领一次；补给/转码为消耗品可重复获得，数量上限各3。每场仍各最多使用1；库存满时不进候选。两次强化合计目标使匹配场景中的有效输出或承伤提高约10%～25%，不同量纲不直接相加；达到30%以上须分析是否因跨过关键击杀/施放阈值，不能仅凭比例自动削弱。

招募方向：漏洞队候补晨读或应援（资源稳定/生存交换），护盾队候补发明家或分析员（覆盖/转混合）。护盾最小队只有守护者时首次160吸收需要更多技能周期，允许比完整队慢；“最小可启动”和“8～12秒标准队”分开验收。

局外成长本轮采用现有基础档进行验证，不新增攻击/产码永久加成。未来内容解锁可提供新选择，但两条基础链不以局外刷数值为通关前提；已有局外属性升级仍保留运行行为，必须另测最高已有升级档，不能用无成长基准代替老存档体验。

### 敌阵压力、时机与三场推演

v0.2将敌方总HP提高到1500/1640/2040，是给验证、预警与第二次破解留出空间。普通供盾下降20%，敌人伤害暂不增加，避免同时提高敌方输出与有效生命而不知失败原因。

|敌阵|主要压力|漏洞队该做什么|护盾队该做什么|可见反制而非硬克制|
|---|---|---|---|---|
|巡逻|广播12秒供盾，四敌普攻持续承压|优先解决可触达目标，能触达广播再集中它，不要求穿前排|前排相邻吃盾，约10～12秒反冲打多敌|广播死后供盾停止；普通伤害可击破盾|
|教室|黑板12秒排伤65|将暴露集中黑板，争取少吃后续排伤|看到9秒预警后留盾到约10～11秒|初始站位分散可少挨排伤；不要求战中拖动棋子|
|巨像|12秒半径2格75重击|保住输出位，逐个减少粉笔干扰|在聚集爆炸收益与承受范围伤害之间取舍|预警展示范围，但不能假设玩家能战中手动躲避|

定时技能预警不是承诺一定打中全队。人物自动移动可能离开范围；本版没有增加玩家战中拖动功能。预警时点固定是为了教学可读，后续随机化前先验证两种程序的释放窗口。

巡逻示例：0秒按阵容开始→约5秒首个自动小连锁→约9秒看到广播预警→约10秒已有资源时决定现在追击还是保留→12秒敌方盾生效→约20秒第二次程序收尾。若15秒就全灭敌人，先判断阵容/成长是否为极端样本；若无成长常态15秒结束，则增加有效敌方生命或削减爆发，不能加演出拖时间。

教室示例：不要求等12秒伤害后再补盾，约10.5秒施放的5秒反冲应覆盖12秒技能；但此前普攻可能提前破盾，所以预览只提示覆盖时长，不保证完美挡住。选择11.5秒释放有更高覆盖机会，暂停支持观察，效果不设计成0.1秒精确操作奖励。

巨像示例：两个前排相邻使并肩和反冲覆盖更好，也容易同吃重击；分散降低敌方AoE命中但可能失去守护者第二目标。战前给两种布阵提示，不显示“唯一正确站位”。

### 验证验收与调参优先级

先验收规则不变量：每份验证机会一次；追击不生追击；每层反冲一次爆炸；资源守恒与上限；失败重试不重抽奖励；取消/无目标不付费；每场热修复一次；正文、资源与预览数值一致。

### 设计目标与技能适用性

体验承诺是“战前能搭出链，战中能改变一场战斗，战后能选择让哪一环更好”。计算机专业的表达来自扫描、交叉验证、确认、权限与故障反冲的实际因果，不靠堆术语。破解仍服务于同一生命战斗；这两条流程暂不加入独立第二胜利进度条。

本轮使用用户指定roguelike的局内资源/奖励分布，以及card-game的费用曲线、效果队列和支付原子性。二者不是专门的战斗数值优化器。主线继续胜利全恢复、失败无限重试，不引入抽牌或永久死亡。

业界方法参考：TFT官方GAT使用预设阵容对照模拟，并把单位职责、成型路径和实际试玩一起审查；官方也指出静态战斗模拟不足以验证完整游戏节奏。本项目据此把“能赢”“有时机取舍”“玩家能解释选择”分别验收，不把一个胜率视为有趣。[官方方法](https://teamfighttactics.leagueoflegends.com/en-us/news/dev/talking-tactics-game-analysis-team-gat/)。三选一强化可借鉴其选择改变构筑方向的方式，本项目的费用与数值均为原创初值。[强化机制说明](https://teamfighttactics.leagueoflegends.com/en-au/news/game-updates/gizmos-gadgets-set-mechanic-overview-hextech-augments/)。

首轮接受的节奏：无成长正常布阵的专精队在普通战约20～40秒完成，护盾队通常比漏洞队慢；Boss约25～45秒作为本次实验接受区间。首次核心程序正常约8～12秒，高压护盾约7秒与低压12～16秒可接受。总施放次数包括热修复，不能把“首个程序”误写为“首个核心程序”。不为凑时长给低血敌人补无提示护盾或延长演出。

### 基础战斗口径补全

- 四人上阵、两个程序槽、一个装备槽/人。羁绊只统计出战人物，候补不计数；开战锁定激活结果，成员退场不关闭羁绊。两标签均为2人门槛，不新增3/4人档。
- 普攻与自动技能沿用原动作时钟；技能在第N次合法普攻出手时附加。代码按第3次有效普攻命中累计，打盾算，技能/追击/爆炸不算。两种计数可能因弹道落空而不同。
- 所有码库存及吸收余量每场从0开始。代码粒子提供可见反馈，库存按模拟结算即时到账，不让玩家手动拾取，也不让粒子抵达时间决定费用。
- 同批先处理支援效果、再结算伤害、再处理由该批产生的非递归反应；稳定ID决定同条件顺序。致死破盾仍能爆炸，但治疗/应急备份不能救回该批已死亡的人。
- 已在途攻击不因暴露强行改目标；只调整下一次合法目标选择。远程暴露不承诺近战能触达，范围爆炸也不承诺后排命中。
- 特殊反冲盾为独立30点层，优先吸收。普通盾不能冒充反冲；到期/破碎爆炸一次，覆盖/驱散/战斗结束不爆炸。盾容量144，不通过覆盖或裁剪产紫。
- 释放前验证目标、库存、颜色、使用次数和冷却，验证成功后一次性扣费。无效目标、取消预览不扣费。点击详情暂停观察，按钮采用“释放”“使用”“转码”等短名称。

### 两条完整链的操作依据

**漏洞队：守护者、冲刺手、分析员、远射手；带追踪破解+热修复。**

分析6秒机会→另一人验证，确认8秒并蓝+1/0.8攻击追击→攒蓝3红1→追踪45伤害、暴露5秒→每名存活友军首次命中额外1.0攻击。普通验证共享4秒冷却；基础追击与暴露追击都不产码，不推进技能，不触发自身。

四人均能命中时一次程序的额外原始伤害为153；仅分析员/远射手命中则101。该差异就是站位价值，不用无视射程的全队自动冲刺抹掉它。防御20时逐事件结算，不能把153当实际扣血。

施放选择：
1. 确认目标仍有较多HP，且至少两个友军可触达时，追踪有较稳定收益。
2. 为尚未触达的后排等太久，会错过当前确认窗口；不用“必须破解广播”做教学门槛。
3. 关键近战将死时，可以先热修复，接受蓝/红支出与共享3秒冷却带来的追踪延后。
4. 暴露将结束时，不补发本来未触达者的追击。目标被45点伤害杀死也不自动转移暴露。

**护盾队：守护者、冲刺手、发明家、应援者；带反冲护盾+热修复。**

普通盾被实际打掉→全队累计80吸收产紫1→紫2绿1→全体30盾/5秒→各盾破碎或到期半径2格30伤害。开场容错两盾各20/5秒；每次80吸收额外最低伤者治疗8。紫色来自全队真实吸收，不按紫色人物人数倍乘，也不按发盾量发码。

一轮四人反冲最多120真实吸收，长期回流最多1.5紫当量，小于成本2紫；剩余紫仍需普通盾承伤。到期空盾能爆炸但不回流紫。强化不能同时降低80阈值并增加30特殊盾，否则需重新计算自循环。

施放选择：
1. 在前排接触敌人时释放，兼顾保护与近距离爆炸；后排30盾仍提供防护，但不强行变全屏伤害。
2. 接近排伤/重击预警的释放窗口，先看前排是否能撑住；早放可能被普通攻击提前破盾。
3. 低压时不能为了凑首发时间故意送脆皮。攒码慢应先检查供盾对象，不先降低吸收阈值。
4. 短时间内救住冲刺手可能比立刻反冲更好，因为活着的输出会持续减少敌方行动。

**混合队：守护者、应援者、分析员、远射手；带两核心程序。**

定位为进阶替换方案，不承担第一次教学。应援者放后排，单守护者根据敌阵选择居中或偏侧承伤；不能为了“两前排”把应援者硬塞前排。这里只有守护者主要供盾，紫色较慢，不能按护盾标准队验收首发。两核心共用3秒冷却，追踪与反冲争抢释放窗口，且失去热修复救急。拥有两羁绊不等于能无限循环两种程序。

### 实际布阵对照与解释

以下槽位按现有部署六槽0～5记述；棋盘的逻辑前排槽0/1/2、后排3/4/5，视觉左右映射沿用原界面。敌人和动作规则均来自原模拟器；无道具、装备、训练、局外加成，除注明外核心程序合法即放、热修复不自动使用。

|队伍/推荐测试布阵|巡逻|教室|巨像|

同阵、同策略的具体反例：
- 护盾改成前排0守护、1冲刺时，巡逻47.20秒，冲刺14.10秒退场；换两人的位置后27.80秒且全员存活。先看谁承压，而非“护盾流输出不足”。
- 保持这个较差护盾位置，8.20秒热修复救低血者，首次反冲由9.20延后到11.40秒，却27.80秒全员存活结束。说明通用程序是有机会成本的战术工具。
- 漏洞相邻前排方案原本巨像32.60秒失败；低血且缺60HP时使用热修复，13.20秒救援后26.20秒获胜。它不能保证所有坏站位都赢。
- 临时将冲刺HP290改成320，较差护盾位置也从47.20变27.80秒。仅10.3%血量变化就跨过循环存活门槛，因此首版不采用这个基础加血；优先保留救援和布阵的价值。

所有推荐三队在上表具备可行路径；这不能证明七人任意组合均可通关。晨读替换队、强化叠加、原初始鞋与最高局外档仍分别验收。

### 敌人：用三场考三件不同的事

基础七敌的HP、攻击、防御、射程、技能沿用“七类敌人与三敌阵”。首版仍使用12秒首发、3秒预警、之后每10秒重复的定时技能，不增加第二套无提示维护盾，也不引入破解专属无敌。

|节点|战前提示|战中玩家决定|可核对的战后信息|
|---|---|---|---|
|巡逻：纸甲/课桌/广播/飞页，总HP1500|广播12秒给另外三敌各40盾/5秒；飞页技能会找后排|保护冲刺输出；可触达广播时集火；用反冲对付近距离多敌|谁最早退场、广播释放次数、程序时间|
|教室：黑板+两粉笔，总HP1640|黑板锁定人数最多横排，每人65伤害，预警3秒|战前分散后排；共享冷却下先追踪还是留盾；不要求战中拖动|锁定排与实际命中、护盾吸收、关键输出是否存活|
|巨像：巨像+两粉笔，总HP2040|巨像锁定一个位置，半径2格75伤害，预警3秒|双前排分摊还是贴近供盾；减少粉笔还是追踪巨像；保留一次救援|预警范围、首个阵亡、程序/治疗是否改变结局|

黑板横排区域固定在预警时选择的逻辑y带，宽度按距离中心y≤0.5；释放时按当前人物位置判定。巨像中心固定在预警时锁定的位置，不跟踪移动。死亡取消未释放技能。玩家不能战中拖动时，预警的操作意义是施放/留资源以及下次重新布阵，不展示虚假的“点这里躲避”。

额外对照将黑板/巨像重复间隔改为12秒，18个非巡逻样本中多数结束时长不变，说明只改冷却并没有证明时机更有趣。本版不把该实验纳入默认规则，也不同时增加Boss生命；后续先比较明确的预警释放策略与真人选择。

### 道具：短期修补资源缺口

仍用现有两道具：补给任选一种+3，转码源2→另一色2；每局初始各1、库存各≤3、每场各最多1，彼此共享3秒使用间隔，与程序冷却独立。容量不足时不部分吞道具，提示缺多少空间。道具使用可早于自然首发，评估时单独列组。

代码补给主要用途：提前第一发、补缺色、救回即将断掉的链。转码器主要用途：将即将溢出的红码换为蓝/绿/紫。它们不能绕过“追踪必须已确认”、10秒程序冷却、3秒共享冷却及反冲真实吸收限制。

胜利提交道具扣费；失败/中途恢复仍按原战前检查点恢复库存，不另加失败损失。道具的跨战斗机会成本来自成功战斗后的库存减少，不能宣称失败会永久消耗。

### 八项强化与原成长统一

八项链路强化沿用v0.2表：集中训练10%HP/8%攻击，镜片首次普攻扫描，协同验证0.8→1.1，贯穿额外50%，并肩开场20→35，应急45盾/5秒一次，缓冲5→6.5秒，隔离爆炸30→36。每项每局限一次，固定盾/爆炸/治疗不随攻击训练放大。

专属奖励需要对应人物在本局名单；程序奖励需要程序可用；装备需要有合法携带者。当前新候选已按携带程序和人物名单过滤：并肩需要本局至少两名不同容错标签人物，协同需要分析员及另一漏洞标签人物；候补计入可选搭档，不代表上阵羁绊已经激活。镜片／备份要求至少一名普通及战斗装备槽都为空的人物。此过滤只用于新抽取，已写入检查点的旧候选不重抽、不删去。镜片和备份不能同人同穿，也不能与篮球鞋同槽。协同提高的是**分析员标记被别人验证时验证者的追击倍率**，不是分析员自己的技能倍率。贯穿只穿主目标后方纵向1.5格内、距射线≤0.35的一名敌人，仍需在射手射程内；无目标就不多打，不能贯穿前方或全地图。

篮球鞋穿守护者的新0.90提案，三个推荐队×三个敌阵共9样本均可获胜；混合巡逻31.05秒仍与无鞋相同，说明它不是免费的完全容错。当前0.75档也已另列9样本，属于旧主线档，不能将无鞋表冒充当前默认玩法。

**新局训练统一（已接入）**：所有新奖励采用“选一人生命+10%、攻击+8%”同一口径，每人最多2份，集中训练计入这两份且每局仅领一次；不另加旧50HP/5攻击叠加。以角色基础属性加法累计份数，最后加装备/已有局外固定加成，再按统一规则取整：
HP=round(基础HP×(1+0.10×份数)+固定HP加成)；
攻击=round(基础攻击×(1+0.08×份数)+固定攻击加成)。
两份合计20%/16%，不连乘，不提高固定盾/治疗/爆炸；鞋只影响间隔。攻击/防御的其他旧增益须在各自来源注明，不能偷偷再乘一遍。

主线scenes/expedition/expedition.gd按原ShortRun的growth_rules分辨预算：新局为2，普通／集中训练合计每人最多2份，从角色基础属性加法累计，再加装备和局外固定值；旧活动局为1，保留基础属性加普通训练和装备后再乘集中训练、最后加局外HP的原顺序。集中训练两项倍率仍读取同一Resource，不改变固定盾／治疗／爆炸。规则版本和训练记录使用原构筑schema8，不建立平行存档。

旧schema1～7活动探索载入时采用growth_rules=1，训练份数不裁剪，已冻结奖励与已获强化保留；再次写回schema8仍记录版本1，旧局沿原口径结束。新schema8只接受版本1或2；版本2拒绝超份数及同人重叠装备的坏档。最高旧成长仍需整场压力测试，普通主线通关不以刷局外属性为前提。

### 三战中如何成型和发奖励

原出发页面提供“追踪队伍”“护盾队伍”，说明角色、链路与缺少的伙伴；正式区域和终局另有“沿用队伍”。选择后仍走原整备、装备与程序页面，不锁定阵容。分析员是原新局已有基础候补；发明家仍通过原人物事件取得，不假定全部永久人物已解锁。

- 选漏洞：保证分析员+远射/冲刺，以及追踪+修复。推荐四人组与一次可选站位提示；没有分析员时，不默认装追踪让玩家等不存在的扫描。
- 选护盾：保证守护+应援以及反冲+修复；首次完整教学前从既有人物事件保证发明家本局可选，使护盾标准队可体验。仅守护的最小启动队单独验收，不强迫它达到完整队8～12秒。
- 对应人物/程序的基础可达性不靠稀有随机；新角色仍按既有剧情兑现永久解锁，不借数值方案绕过纪念内容。
- 第一战使用基础链；第一奖励选可靠性/救援方向；第二战出现明显预警；第二奖励选爆发/覆盖方向；第三战组合检验。三战是取现有主线节点的样本，不创建独立入口。
- 三选一继续采用A成型链、B通用、C替换方向的过滤/无放回权重，见v0.2权重表；原装备/新训练候选纳入B/C，各权重2，原旧大数值训练不混进新规则池。
- 第一次排除缓冲/贯穿，第二次起开放。至第二次奖励至少展示一次适配候补招募；展示保底不强制领取，不挤掉链路A槽。
- 池耗尽时合法补给/转码各权重2，满库存过滤；仍不足就展示较少合法候选。候选入检查点，失败不重抽。

两个典型成长方向：漏洞选择镜片+协同，提高启动机会和每次验证收益；或协同+贯穿，牺牲初次启动强化换多敌输出。护盾选择并肩+备份，提高承压可靠性；或并肩+隔离，提高开场与爆炸；缓冲+隔离面向盾不易被快速击破的敌阵，但缓冲会推迟到期爆炸。示例不意味着固定发这两件，选择结果来自合法三选一。

|阶段|漏洞队重点|护盾队重点|应该让玩家看到|
|---|---|---|---|

预览追踪显示已确认剩余秒数、目标HP/盾、当前可触达友军人数；预览反冲显示存活受盾人数、盾量/时长、当前爆炸圈，后续移动可能改变命中；预览修复显示本次有效治疗、支付颜色和核心还缺多少。不能把最大收益显示为保证收益。战报至少给出真实首次核心时刻、程序次数、四色生成/花费/溢出、盾真实吸收和首个退场。没有成对实验时，不能写“这次操作让你获胜”的因果结论。

### 本次证据、限制和后续验收

基线b55139d，Godot4.7.2 Windows，PowerShell7，原game/combat/code_battle_simulation.gd与现有Content/Encounter；固定逻辑步0.05秒，无随机种子变化。

共完成81个基线配置（3队×3敌阵×3布阵×3核心策略），以及45个布阵/冲刺HP对照、27个预警周期对照、39个装备对照、12个热修复对照。合计204次确定性运行，其中包含重复基线，**不是204个独立样本，更不是随机胜率**。每次均完成结算；这些诊断不等于所有旧规则检查或完整校园流程通过。

### 单行动条、产码进度与敌人意图

每个存活单位仅有一条行动计时条：普攻蓝青、施法金橙，常驻只显示比例；施法用沙漏或敌方技能图形辅助颜色区分，“普攻／施法／接近”与剩余秒数放到状态详情。满条表示本次动作释放，不代表远程弹道已命中；收招时保持满条。冷却已好但未进射程时显示“接近”，不会假装已经释放。生命与护盾共用一条数值槽，生命在左、护盾在右，中间显示“当前生命/最大生命+护盾”，无盾省略加号部分。生命固定左端，受伤时向左缩短；护盾固定右端，减少时左边缘向右缩。生命独立使用最大生命刻度，满血填满生命槽；护盾有值时在右侧附加最多24像素的紫色段，没有护盾时收起。历史盾量不挤占生命宽度。血量／盾数字立即更新，填充约100～160ms追到目标；战斗重建重置显示缓存。血条、行动条保留图标，护盾图标位于合条右侧，类型图标均用深色底板。

达到原技能普攻次数后，先完成该次普攻及收招，再执行独立技能。普通技能准备0.8秒、收招0.2秒；已有计时敌人的预警即真实3秒蓄力，若正执行普攻则先完成当前动作。施法冻结普攻冷却与移动，结束后继续剩余冷却，不重置；攻速不缩短施法，普通受击不中断，阵亡取消未释放技能。继续复用原动作准备／释放／收招映射，不增加人物、敌人或动作素材。

产码进度与技能次数分开：红、蓝、绿人物旁显示对应符号与按规则阈值生成的离散节点，详细命中数／阈值在悬停详情中显示，读取 simulation.attack_counts，而非 skill.attacks_to_trigger 或 count。紫色读取全队实际护盾吸收余量，在顶部权限库存卡内显示“全队吸收 x/80”；它不是某个人的当前护盾，也不是个人攻击计数。团队四色库存为顶部辅助单行；底部中央两张破解卡是主要操作区，显示名称、费用与缺码／可释放／确认释放／冷却／待目标等状态，每场首次就绪仅强调一次。只有真实入库事件提供短促边框反馈，溢出不伪造入库成功；简化特效收敛动态。

友方状态悬停显示生命／护盾、产码或共享吸收及行动时间的简要信息，点击展开并固定详情。敌人意图独立跟随身体旁的圆角思考泡泡显示，两颗渐小圆点指向人物，普通浅色边、施法金色边；普攻剑形、施法按实际护盾／范围技能区分；悬停显示名字、技能说明、目标和剩余秒数，同时暂停战斗供阅读。点击固定，Esc或点击空白关闭，操作暂停不修改手动暂停。切换页面、死亡或重建战斗清理失效意图。人物状态保留紧凑行动细条、带底色的产码图标与节点；生命护盾数值常驻居中。思考泡泡32×28，悬停热区32×36逻辑像素，绘制与交互共同跟随身体。单位状态位于人物侧下方，减少上排状态遮住下排人物；混合动画和帧动画共用脚底根排序，动作位移不改变前后层级。

当前运行组件已在明确授权下试接入战斗状态纹理家族，文字、数字与进度仍为原生绘制。密集状态框在战场内邻近避让并以引线指示归属，意图热区与显示位置一致。个人产码强调只响应本人物同色的普攻产出，团队吸收／道具不误闪个人普攻计数。资产及接入效果仍待评审，审批维护于[对应美术任务](art/tasks/battle-status-components.md)，不能将逻辑验证当作美术批准。实施与三尺寸验证见UI-02，真实计时与链路边界见COMBAT-02。
