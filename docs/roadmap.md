# 项目 Roadmap

## 依据与取舍

基于 [2026-09-14 实现状态核验](implementation-status.md)，代码基线 `1ad601f`。这里仅维护未来体验目标、优先级和验收；规则、数值、素材规格引用主题文档，不复制维护。

当前已有短局、续玩、奖励、成长和多人派遣闭环。下一步的高价值投入是把这些能力整理成**陌生玩家能独立完成、失败后知道如何调整、可以交付试玩的校园短篇**，而非再扩充一轮框架。当前检查存在随机通关与图鉴夹具红项；它们是里程碑前置，不能视为已有稳定基础。

用户此前明确的最晚 **9 月 27 日**为外部截止约束；没有产能数据，不按剩余日期编造每日工期。下列成本为相对小／中／大，不是日数或交付承诺；内容数量与平台范围若超出容量，优先缩减扩展，保留闭环、结局和必要平台验证。

## 当前里程碑 M0：可靠且可独立完成的短局试玩版

- **玩家目标**：从菜单进入，理解部署与路线，完成短局和结算；失败能够调整重试，中途离开可以继续。
- **为什么现在做**：闭环已经存在，当前主要损失来自验收红项、上手门槛与交付未知；继续堆内容会放大这些问题。
- **依赖功能**：CORE-01、COMBAT-01、COMBAT-02、COMBAT-03、COMBAT-04、DEPLOY-01、DEPLOY-02、RUN-01、RUN-02、REWARD-01、REWARD-02、SAVE-01、SAVE-02、UI-01、UI-03、RELEASE-01、RELEASE-02。
- **工作范围**：先定位 E13 的四条 Boss 路径，区分规则错误、平衡变化与过期测试策略；修复 E17 夹具并回归实际图鉴战斗恢复。补最短的部署／奖励引导，评估逐场空部署摩擦。对当前版本做可分发构建及目标浏览器冒烟，尽早以真机暴露点击、字体和存档风险。清理状态索引中列出的主题文档历史歧义。
- **明确不做**：新战斗架构、多区域、商店、合成、批量人物制作、扩大派遣规模；不为了让检查变绿删除失败样本或降低断言而不解释设计依据。
- **验收**：现有有效检查通过；随机失败样本有明确原因、处理依据及回归证据，主线不强制购买成长。图鉴检查确实开战后执行。陌生试玩者能独立走完至少一局并完成一次失败重配；记录实际时间和卡点。当前构建可从目标入口进入、结算、离开再续玩；未通过的平台明确标边界。
- **主要风险**：一套固定策略通关不等于公平；测试夹具可能跟不上玩家规则；桌面逻辑通过不代表触控可用。
- **成本**：中；若发现浏览器存档或移动布局问题则需重新估算。
- **与下一阶段关系**：形成 M1 可依赖的稳定流程、真实试玩数据与最小发布通路。

## 近期里程碑 M1：有起因、有变化、有收尾的校园短篇

- **玩家目标**：清楚为何探索，战斗与事件有校园意义，通关后看到一次可感知的恢复与结尾；回基地有继续玩的理由。
- **为什么现在做**：目前资源循环成立，纪念目标尚未形成体验；少量完整叙事比新增独立系统更接近项目目的。
- **依赖功能**：CORE-01、CORE-02、RUN-02、REWARD-01、META-01、META-02、SAVE-01、CONTENT-01、CONTENT-02、CONTENT-03、ART-02；前置 M0。
- **工作范围**：围绕现有短局形成开场、少量关联事件、Boss 前后反馈、基地恢复成果与可重看收尾。先用虚构角色完成可替换内容样本；实际人物／校园素材具备后再替换。把升级与派遣收益解释为可见的校园进展，优先复用界面与资源系统。
- **明确不做**：覆盖全班、完整多章节剧情、每地点独立背景、复杂分支结局；不要求刷满成长才能看到主要结尾。
- **验收**：试玩者能说出目标及通关改变；一局从开头到结尾连贯，回忆／恢复标记重复通关不重复解锁且续玩一致。结局不依赖等待派遣或刷数值。内容更改仍遵守冻结快照和旧档边界。
- **主要风险**：真实素材缺失、叙事范围膨胀、把资源到账误当作恢复表达；新永久标记可能需要迁移。
- **成本**：中；真实素材量与演出要求增加时可升为大。
- **与下一阶段关系**：确定完整短篇所需内容和视觉重点，M2 据此深化而不盲目扩表。

## 中期里程碑 M2：值得重玩的构筑与清楚的战斗反馈

- **玩家目标**：路线、角色、装备组合带来可解释的打法差异；重新游玩有新的取舍。
- **为什么现在做**：在 M0 的平衡与试玩数据、M1 的内容边界明确后，扩充才容易判断价值。
- **依赖功能**：COMBAT-02、COMBAT-03、COMBAT-04、RUN-01、REWARD-01、REWARD-02、CONTENT-01、CONTENT-02、ART-01、AUDIO-01；前置 M0，内容方向受 M1 约束。
- **工作范围**：通过少量针对性敌群、装备和事件，形成至少两种可解释打法；改善目标／技能／贡献反馈，添加必要命中和技能声音。按实测调整战斗与阅读节奏。把核心检查收拢为有超时、明确失败和独立存档的可重复入口；在实际改动痛点处拆分场景职责。
- **明确不做**：为凑局长加重复战斗、TFT 式经济、多槽随机词条、大规模框架重写；不以增加血量代替策略。
- **验收**：试玩中能观察到不同阵容或装备分配应对不同敌群，玩家能够解释至少一个调整理由；初始选择保留可通关路径；样本种子、奖励选择和结果可复现；音频跟随命中且暂停／倍速符合预期；新增内容通过注册、旧档和两套装备入口回归。
- **主要风险**：选择名义多但最优解唯一；动画／音频掩盖关键信息；长局目标与轻量玩法冲突。
- **成本**：中，若扩充新机制则大。
- **与下一阶段关系**：形成较稳定的内容集和反馈事件，正式美术可据此集中生产。

## 后期里程碑 M3：可发布的纪念版本

- **玩家目标**：在承诺支持的设备上顺利下载或打开、理解文字、完成主线并保存进度，整体观感一致。
- **为什么值得做**：M0 只解决早期交付风险；正式发布仍需当前内容集、资产版本和真实设备的整体验收。
- **依赖功能**：CORE-02、CONTENT-03、ART-01、ART-02、ART-03、ART-04、AUDIO-01、UI-01、UI-02、UI-03、UI-04、SAVE-01、SAVE-02、RELEASE-01、RELEASE-02；前置 M1，M2 按容量纳入。
- **工作范围**：优先补高频出场角色与敌人，按 [美术工作流](art/WORKFLOW.md) 完成具体版本审批；统一入口和结束画面，核对来源与许可证。补目标设备的触控、字体、布局、声音和存档实测，验证当前导出及实际发布入口，去除模板身份与不适用发布配置。
- **明确不做**：所有平台首发、全量角色同规格动画、云存档、账户系统；不把待评资产自动升级为 approved。远程发布另按用户授权执行，不因本 Roadmap 自动推送。
- **验收**：承诺平台的完整新局／失败重试／退出续玩／通关流程通过；浏览器刷新与站点存储边界说明准确；关键文本可读、关键操作可触达；使用资产版本、批准依据和游戏接入截图对应；交付包与验证版本可追溯。
- **主要风险**：平台问题发现过晚、人工评审返工、真实人物素材与授权不足。
- **成本**：大；可通过缩减人物数量和首发平台收敛。平台试验已在 M0 前移，不等此阶段才开始。
- **与后续关系**：建立稳定发布基线，扩展内容单独验收，避免破坏首发存档。

## 可选里程碑 M4：通关后的额外挑战

- **玩家目标**：愿意继续的玩家能自选更有压力的挑战，主要纪念内容仍可在普通主线获得。
- **为什么后置**：主线平衡与内容闭环尚需验收，挑战不能代替它们。
- **依赖功能**：RUN-04、COMBAT-04、SAVE-01、CONTENT-01；前置 M1、M2 与稳定基线。
- **工作范围**：先做一个可解释挑战条件、限次重试与独立记录，明确挑战失败／重开／恢复规则；是否加入派遣标签事件另按 META-04 的实际玩家价值判断。
- **明确不做**：排行榜、赛季、多层难度叠加、强制刷挑战解锁主线结局。
- **验收**：普通与挑战存档状态不串用；次数扣除、续玩、胜败与奖励可复验；挑战有策略变化而非纯粹堆数值。
- **主要风险**：维护双规则成本、重试状态漏洞、奖励反向逼迫普通玩家。
- **成本**：中；可取消，不阻塞首发。
- **与后续关系**：验证重玩需求后再决定是否增加内容；多区域与其他扩展不自动进入计划。

## 关键依赖、并行与串行

| 关系 | 执行约束 |
| --- | --- |
| COMBAT-04 → 新敌群／装备平衡 | 先解释随机回归失败，再扩充；否则难以区分新内容与旧回归 |
| DEPLOY-01 → UI-03 检查 | 先让夹具真实部署开战，再验证图鉴冻结／恢复 |
| CONTENT-01、SAVE-01、SAVE-02 → CORE-02 永久进展 | 先确定新增状态与迁移边界，再接一次性收尾和回忆 |
| ART-01、ART-03 → ART-02 扩充 | 复验工具后按角色小批量生产；遵守 ART-04 阶段审批 |
| RELEASE-02 → 发布范围 | M0 做早期实机和导出探针，M3 对最终版本完整验收 |

**可并行的工作流**：回归问题定位与短篇文案草拟；现有资产评审与目标包测试；资源内容小样与存档边界设计。这里表示工作依赖允许，不自动授权新建任务或多代理施工；共享 checkout 应避免同时修改同一组资源与快照定义。

**必须串行**：复现失败 → 判断产品规则或夹具问题 → 修改 → 行为回归 → 更新状态 → 本地提交；永久状态设计 → 迁移与幂等验证 → 叙事接入；具体版本概念 → 资产 → 接入评审；构建产物 → 真机验证 → 对外声明支持。

## 高风险未知与暂缓

| 项目 | 当前处理与理由 |
| --- | --- |
| 随机路径失败原因、图鉴恢复证据 | M0 优先消除未知，不以旧摘要绿灯放行 |
| 主线时长、上手难度、逐场空部署负担 | 用真实试玩计时与操作记录裁决；暂不承诺已经达到 20～30 分钟 |
| 浏览器保存、触控与中文资源 | M0 提前验证；旧版 Web 成功不能证明当前版本 |
| 普通局内操作保存失败的内存状态 | 区分交易回滚和提示重试；M0 验收时明确边界，按实际故障价值修复 |
| 全班人物数量、纪念素材、批准返工 | M1 确定最小表达，M3 按高频资产优先；不用旧提案数量当承诺 |
| 商店、多区域、消耗品、羁绊、购买合成 | 暂缓 RUN-03；当前已有构筑途径，新增规则与 UI 成本高 |
| 更多派遣地点、标签收益、挂机经济 | 暂缓 META-04 深化；当前派遣闭环足够，先让已有收益产生校园价值 |
| 全量正式美术、骨骼、根运动、复杂镜头 | 暂缓；先完善高频样本与可读性，避免生产范围失控 |
| 通用编辑器、历史图库、数据库与框架重写 | 继续暂缓；ART-05 的当前项目只读资源浏览与准确预览是已完成的窄范围例外，不扩展为审批、编辑、自动生图或跨项目平台 |
| 云存档、账户、排行榜、多平台齐发 | 暂缓；本地单机纪念目标不依赖这些服务 |

新增里程碑或调整范围时同步此文；普通功能完成只更新实现索引及主题文档。当前推荐先执行 M0，完成后用实际试玩与发布证据决定 M1/M2 的投入比例。
