# 项目 Roadmap

## 依据与取舍

2026-09-16 用户确认范围调整：M1 为完整战役骨架与图书馆单地点精制，替代此前单局短篇范围；当前制作只允许空占位或静态资源。下方 M0 保留历史验收范围，现行新增范围以 M1 章节为准。

基于 [2026-09-15 实现状态核验](implementation-status.md)，功能验收基线 `7fe7529`，文档整理基线 `467784e`。具体状态见[功能实施目录](implementation/README.md)。这里仅维护里程碑、优先级和验收；规则、数值、素材规格引用主题文档，不复制维护。

M0 已完成工程验收：短局、续玩、奖励、成长和多人派遣闭环可运行；随机路线可通过失败后重配完成，图鉴从真实战斗进入，阵位沿用与上下文提示已接通，当前 Web release 包完成桌面全流程及刷新恢复验证。下一步进入 M1，把稳定短局变成**有起因、有校园变化、有收尾的纪念短篇**。陌生玩家试玩与手机真机仍是待验边界，将随 M1 尽早验证。

用户此前明确的最晚 **9 月 27 日**为外部截止约束；没有产能数据，不按剩余日期编造每日工期。下列成本为相对小／中／大，不是日数或交付承诺；内容数量与平台范围若超出容量，优先缩减扩展，保留闭环、结局和必要平台验证。

## 已完成里程碑 M0：可靠且可独立完成的短局试玩版

- **玩家目标**：从菜单进入，理解部署与路线，完成短局和结算；失败能够调整重试，中途离开可以继续。
- **完成价值**：消除了随机路线和图鉴夹具的错误红灯，减少重复部署操作，并建立当前版本可分发与恢复的证据基线。
- **依赖功能**：CORE-01、COMBAT-01、COMBAT-02、COMBAT-03、COMBAT-04、DEPLOY-01、DEPLOY-02、RUN-01、RUN-02、REWARD-01、REWARD-02、SAVE-01、SAVE-02、UI-01、UI-03、RELEASE-01、RELEASE-02。
- **完成范围**：E13 通过真实战报—重配—重试覆盖四条原失败路径；E17 改为真实部署并开战后验证图鉴冻结与恢复；首战短提示和后续阵位沿用已接入；部署与覆盖层交互缩短；当前 Web release 包完成桌面全流程、Boss 前刷新及战斗开始后刷新恢复；主题文档已按现行行为消歧。
- **明确不做**：新战斗架构、多区域、商店、合成、批量人物制作、扩大派遣规模；不为了让检查变绿删除失败样本或降低断言而不解释设计依据。
- **验收结果**：E13、E17 及相关部署、短局、存档回归通过；桌面 Web release 包可从目标入口完成短局并刷新续玩。主线样本无需永久成长，但四条路径需要失败后重配。844×390 仅完成风险探针，明确不判定手机可用。
- **遗留边界**：尚无陌生玩家独立通关、实际局长和 Android／iOS 真机证据；它们转入当前里程碑的早期验证，不改写为已完成。
- **成本**：中，已完成。
- **与下一阶段关系**：M1 可直接复用稳定流程、检查点和桌面 Web 交付基线，集中投入纪念表达。

## 剧情、人物、事件与美术的引入节奏

**M1 完成首发整体设计，并制作一条从头到尾的完整体验；M2 补齐选定首发内容；M3 集中验收和修正。** 完整设计不表示全部内容已经制作或批准。

| 内容 | M1：定范围与完整样本 | M2：补齐首发内容 | M3：验收收尾 |
| --- | --- | --- | --- |
| 剧情 | 主线大纲、开场、关键转折和结尾；实装完整短篇 | 补人物支线、对白和回忆 | 校对与节奏修正 |
| 人物 | 首发名单、角色职责、获取途径；接入核心人物 | 补齐选定人物玩法与表达 | 身份、技能和画面一致性检查 |
| 事件 | 明确事件流程与触发关系，实装主线必要事件 | 增加路线变化与人物互动 | 分支、条件、支付与存档回归 |
| 配套美术 | 资产清单、核心人物、关键地点及收尾同步制作、接入与分阶段评审 | 按首发范围逐批补齐并评审 | 缺陷修正、适配、来源与最终接入验收 |

真实同学和校园资料从 M1 开始引入；未提供的身份与素材明确占位，不自行编造。首发名单和规模仍需用户确定，不承诺覆盖全班。

M1 首个设计交付物为相互对应的**主线大纲、人物职责表、事件流程、配套资产清单**。剧情／人物／事件设计维护于 game-design.md 的现行章节，实际配置进入内容资源；美术具体任务、版本和审批沿用美术目录。设计稿标明待讨论项，不自动视作剧情或美术批准。功能进展分别记录于 CORE-02、CONTENT-03、ART-02 等档案，不把这四项另外做成施工日志。

## 当前里程碑 M1：虚拟校园修复战役骨架（2026-09-16 更新）

- **目标**：短序章、三个固定区域、记忆终端收集、三阶段短终局、永久校园恢复贯通；只精制图书馆一个地点。世界观、人物职责、事件与玩法细则统一见 [现行设计](game-design.md#m1-现行设计虚拟校园修复战役2026-09-16)。
- **范围**：三区域基于真实校园，合计6～8处地点、每路线约4～5处；点击热点探索与可选照片回忆、一次守卫战离场门槛、立即完成的教学派遣、终端数量开放派遣与局内事件、人物区域通关后永久兑现、回忆重看。
- **实施顺序**：战役状态与旧档迁移 → 固定区域与地点访问 → 序章及派遣／人物解锁 → 三阶段终局与恢复 → 图书馆静态样本及整体验收；逐功能验证、截图、本地提交。
- **成本与截止**：大型系统里程碑；9月27日硬截止，首次战役目标60～90分钟，须真人计时验证，不据此承诺工期。
- **美术限制**：开发只用空占位或静态资源，禁止生成动画资产。生成与待生成要求持续维护于 [静态清单](art/m1-static-assets.md)，功能结束向用户报告。动画工具调整不阻塞静态功能开发。
- **验收**：序章到终局完整可玩；三地区任意顺序、重玩、终端和人物兑现、旧档与访问快照恢复正确；至少一次陌生玩家记录；Windows、桌面Web、一台Android横屏实测。图书馆只精制单个地点，其余占位与批准状态明确标注。
- **降级顺序**：优先减少额外照片／回忆量，再降低非图书馆热点量到每处2个，必要时派遣和人物内容保留机制与完整样本。保留回忆页、图书馆真实照片目标、主线收尾、存档与最低设备验收；缺真实资料或真机证据不得宣布整体验收完成。
- **边界**：不制作自由行走、全班内容、复杂分支、全量正式背景或动画资产；主线不要求刷满人物与成长，不等待普通派遣才能看结局。
- **M2关系**：补齐其它地点真实内容、人物、照片和静态资产；独特敌群与打法按证据扩充。动画生产须待工作流稳定及新的明确授权。

## 近期里程碑 M2：补齐首发内容，深化构筑与反馈

- **玩家目标**：路线、角色、装备组合带来可解释的打法差异；重新游玩有新的取舍。
- **为什么现在做**：在 M0 的平衡与试玩数据、M1 的内容边界明确后，扩充才容易判断价值。
- **依赖功能**：COMBAT-02、COMBAT-03、COMBAT-04、RUN-01、REWARD-01、REWARD-02、CONTENT-01、CONTENT-02、CONTENT-03、ART-01、ART-02、ART-04、AUDIO-01；前置 M1 的首发设计与核心短篇基线。
- **工作范围**：按 M1 选定范围补齐人物、支线／回忆、事件和配套美术，每批连同接入、评审一起完成。通过少量针对性敌群、装备和事件，形成至少两种可解释打法；改善目标／技能／贡献反馈，添加必要命中和技能声音。按实测调整战斗与阅读节奏。把核心检查收拢为有超时、明确失败和独立存档的可重复入口；在实际改动痛点处拆分场景职责。
- **明确不做**：为凑局长加重复战斗、TFT 式经济、多槽随机词条、大规模框架重写；不以增加血量代替策略。
- **验收**：选定首发内容和必要资产清单完成或经明确缩减，不以永久占位冒充完成；美术遵守阶段审批。试玩中能观察到不同阵容或装备分配应对不同敌群，玩家能够解释至少一个调整理由；初始选择保留可通关路径；样本种子、奖励选择和结果可复现；音频跟随命中且暂停／倍速符合预期；新增内容通过注册、旧档和两套装备入口回归。
- **主要风险**：选择名义多但最优解唯一；动画／音频掩盖关键信息；长局目标与轻量玩法冲突。
- **成本**：中，若扩充新机制则大。
- **与下一阶段关系**：形成首发内容与配套资产基线，M3 主要修缺陷和做整体验收，不从零开展美术生产。

## 后期里程碑 M3：可发布的纪念版本

- **玩家目标**：在承诺支持的设备上顺利下载或打开、理解文字、完成主线并保存进度，整体观感一致。
- **为什么值得做**：M0 只解决早期交付风险；正式发布仍需当前内容集、资产版本和真实设备的整体验收。
- **依赖功能**：CORE-02、CONTENT-03、ART-01、ART-02、ART-03、ART-04、AUDIO-01、UI-01、UI-02、UI-03、UI-04、SAVE-01、SAVE-02、RELEASE-01、RELEASE-02；前置 M1，M2 按容量纳入。
- **工作范围**：对 M1/M2 已制作的首发内容补缺陷、核对版本，按 [美术工作流](art/WORKFLOW.md) 完成剩余接入验收；统一入口和结束画面，核对来源与许可证。补目标设备的触控、字体、布局、声音和存档实测，验证当前导出及实际发布入口，去除模板身份与不适用发布配置。
- **明确不做**：所有平台首发、全量角色同规格动画、云存档、账户系统；不把待评资产自动升级为 approved。远程发布另按用户授权执行，不因本 Roadmap 自动推送。
- **验收**：承诺平台的完整新局／失败重试／退出续玩／通关流程通过；浏览器刷新与站点存储边界说明准确；关键文本可读、关键操作可触达；使用资产版本、批准依据和游戏接入截图对应；交付包与验证版本可追溯。
- **主要风险**：平台问题发现过晚、人工评审返工、真实人物素材与授权不足。
- **成本**：大；可通过缩减人物数量和首发平台收敛。平台试验已在 M0 前移，不等此阶段才开始。
- **与后续关系**：建立稳定发布基线，扩展内容单独验收，避免破坏首发存档。

## 可选里程碑 M4：通关后的额外挑战

- **玩家目标**：愿意继续的玩家能自选更有压力的挑战，主要纪念内容仍可在普通主线获得。
- **为什么后置**：主线平衡与内容闭环尚需验收，挑战不能代替它们。
- **依赖功能**：RUN-04、COMBAT-04、SAVE-01、CONTENT-01；前置 M1、M2 与稳定基线。
- **工作范围**：先做一个可解释挑战条件、限次重试与独立记录，明确挑战失败／重开／恢复规则；是否加入派遣标签事件另按 META-04 的实际玩家价值判断。
- **明确不做**：排行榜、赛季、多层难度叠加、强制刷挑战解锁主线结局。
- **验收**：普通与挑战存档状态不串用；次数扣除、续玩、胜败与奖励可复验；挑战有策略变化而非纯粹堆数值。
- **主要风险**：维护双规则成本、重试状态漏洞、奖励反向逼迫普通玩家。
- **成本**：中；可取消，不阻塞首发。
- **与后续关系**：验证重玩需求后再决定是否增加内容；多区域与其他扩展不自动进入计划。

## 关键依赖、并行与串行

| 关系 | 执行约束 |
| --- | --- |
| M0 → M1 | 工程回归与桌面 Web 基线已完成；M1 直接围绕纪念短篇增加永久状态与表达 |
| COMBAT-04 → 新敌群／装备平衡 | 现有随机样本已可经重配通关；扩充时继续保留失败—调整—重试的真实流程验证 |
| CONTENT-01、SAVE-01、SAVE-02 → CORE-02 永久进展 | 先确定新增状态与迁移边界，再接一次性收尾和回忆 |
| ART-01、ART-03 → ART-02 扩充 | 复验工具后按角色小批量生产；遵守 ART-04 阶段审批 |
| RELEASE-02 → 发布范围 | M0 已做桌面 Web 与小屏探针；M1 补真机与最低可用布局，M3 对最终版本完整验收 |

**可并行的工作流**：短篇文案与永久状态设计；现有资产评审与手机风险验证；事件内容小样与陌生玩家试玩准备。这里表示工作依赖允许，不自动授权新建任务或多代理施工；共享 checkout 应避免同时修改同一组资源与快照定义。

**必须串行**：短篇目标与恢复结果定案 → 永久状态设计 → 迁移与幂等验证 → 叙事接入；具体版本概念 → 资产 → 接入评审；构建产物 → 真机验证 → 对外声明支持。

## 高风险未知与暂缓

| 项目 | 当前处理与理由 |
| --- | --- |
| 主线时长、上手难度、失败后调整意愿 | M0 自动样本通过；M1 用陌生玩家实际流程与计时裁决，不承诺已经达到 20～30 分钟 |
| 手机触控、中文可读性与小屏布局 | 当前 844×390 探针明确偏小；M1 尽早真机验证并修最低可用层，完整平台验收仍归 M3 |
| 浏览器后台、存储配额与其他浏览器 | 桌面当前包刷新恢复已通过；其余环境保持待核验，不把单一浏览器结果外推 |
| 普通局内操作保存失败的内存状态 | 区分交易回滚和提示重试；M0 验收时明确边界，按实际故障价值修复 |
| 全班人物数量、纪念素材、批准返工 | M1 确定名单与配套资产，M1/M2 按高频内容优先制作评审；不用旧提案数量当承诺 |
| 商店、消耗品、羁绊、购买合成 | 继续暂缓；三个固定区域已明确纳入M1，不再归入该暂缓项 |
| 派遣扩展 | 按终端数量开放新派遣任务已纳入M1；标签收益与挂机经济深化继续暂缓 |
| 全量正式美术、骨骼、根运动、复杂镜头 | 暂缓；先完善高频样本与可读性，避免生产范围失控 |
| 通用编辑器、历史图库、数据库与框架重写 | 继续暂缓；已授权的 [ART-05 项目专用资源台](implementation/art-05.md)提供 Manifest 浏览、版本核验与预览，不扩展为通用编辑或资产平台 |
| 云存档、账户、排行榜、多平台齐发 | 暂缓；本地单机纪念目标不依赖这些服务 |
