## 可视化编辑器

双击 `tools/art/asset_manager/control/ArtManagerControl.exe` 打开原开发工具集，点击“地图编辑”卡的“启动”，再点“打开”。游戏 Debug／Release 使用另一套独立启动器，地图工具保持原窗口入口。

默认地址是 `http://127.0.0.1:8767/`。工具集显示实时状态、PID 和运行目录；关闭工具集窗口不会停止地图服务，完成编辑后可点“停止”。服务只监听本机 `127.0.0.1`。也可不用工具集，直接执行 `pwsh.exe -NoProfile -File .\tools\campus-map-editor\run-server.ps1`；若需另选端口，用 `-Port 8768`，但工具集只检测默认的 8767 端口。纯 Node 调试可执行 `node tools/campus-map-editor/server.mjs --port 8768`，在终端按 Ctrl+C 关闭。

1. 选当前地图选区，再选“选区边界”“路径拐点”或“地图地标”。直接拖动地图圆点；Shift＋点击边线插入顶点。“加点”插在所选顶点之后，“删点”删除所选顶点。
2. 调整地图边缘明暗时，切换到“亮区边界”：黄色闭合线内保持原亮度，线外变暗。拖动黄色顶点、Shift＋点击边线加点；右侧可调日／夜／异常三态的校外亮度和边缘过渡宽度。编辑器画布即时显示日间明暗，夜间和异常请保存后在游戏预览中切换查看。它不等于真实测绘校界，也不改变路线选区或可通行范围。
3. 右侧优先显示当前工具：选区模式显示顶点操作、名称、颜色和探索区域；拐点模式显示当前选区与拐点操作；亮区模式显示边界顶点、过渡宽度和三态亮度；地标模式显示名称和精确 X/Y 坐标。切换工具时侧栏回到顶部。
4. 在选区模式展开“关联地标”，勾选该选区相关的地图标记，它们必须与对应区域的探索地标一致，但不安排游玩顺序。在地标模式展开“添加地标”创建标记。“指定位置”和“探索流程”默认折叠，按需展开。
5. 用“撤销／重做”检查结果；点击“保存地图”才会写入游戏布局文件。每次保存前，旧版自动备份在 `.godot/campus-map-editor-backups/`。也可“导出”JSON 副本；“导入”后仍须点“保存地图”才会生效。
6. 保存会拒绝越界坐标、缺失地点引用、自交区域和超过 32 点的边界。如果另一个程序已改动该文件，编辑器会拒绝覆盖；先导出自己的版本，再刷新页面核对。

这是桌面端开发工具，不会出现在玩家游戏内。当前不提供新战役区域的创建；新增地图选区仍只能映射到已有三个战役 ID。地图地标、路径拐点与探索站点是不同对象；展开右侧“探索流程”可查看当前区域 `.tres` 路径和“配置指南”入口。游玩顺序、分支和内容引用见[区域流程配置](flow-authoring.md)。

## 保存权限错误

如果保存提示“地图文件或目录不可写”，当前页面里的编辑仍然保留，不要先刷新。可先“导出”备份，再从本机开发工具集中停止并重新启动地图服务，然后回到原页面重试保存；另需检查文件只读属性或其他程序的占用。临时文件和旧版备份仍用于保护原地图，不以直接覆盖绕过权限错误。

由 Codex 启动、随后供人工编辑使用的后台服务，需要在正常本机执行环境中运行。受限进程可能能读取项目文件却不能写地图目录；正常权限指离开该受限执行环境，不要求以管理员身份启动。服务代码更新也需要重启服务，单独刷新网页不会重新加载 Node 后端。

## 指定位置交流

在编辑器点击「取坐标」，右侧「指定位置」会自动展开并移到顶部，再点地图上的目标位置。黄色十字标记固定落点，面板显示原图坐标；点击「复制坐标」即可把 `x=1080.7, y=749.9` 这样的文本发到聊天中。「清除」只清除标记；点击任一编辑对象按钮回到编辑模式，坐标面板随之收起并回到辅助区，已拾取的位置会保留到清除或刷新。

坐标与布局共用1800×1500原图空间，不受缩放或滚动影响，不是屏幕像素或经纬度。拾取不修改地图，不需要保存，也不进入撤销记录；刷新页面后标记消失。自动复制受浏览器限制时，输入框会选中文字，可手动按Ctrl+C。

## 直接编辑 JSON

- 改地标文字或落点：在 `places` 中找到 ID，改 `title` 或 `point`。例如 `"library": {"title":"图书馆", "point":[720,755]}`。
- 新增地标：在 `places` 中添唯一英文 ID、文字和坐标，地图标记与文字会出现。放进某条路线的 `places` 后，需同步在 Godot 区域配置探索站点；关联地标与实际路线不一致会被启动预检拒绝。
- 改选区关联地标：调整 `routes[].places` 的成员。该列表不安排探索顺序；选区文字名称改 `title`，画线用的 `path` 需按源图顺序列出至少两个 `[x,y]`。关联地标不会自动生成线条。
- 改高亮范围：调整 `area` 多边形顶点，沿边界顺时针或逆时针依次写入，不要自交，至少 3 点、最多 32 点。首尾无需重复。该范围同时用于鼠标命中和区域高亮，不等于可通行导航网格。
- 改校外降亮度：调整顶层 `light_boundary.points` 闭合多边形，线内原亮度、线外按 `outside_brightness.day/night/anomaly` 分态降低亮度；`feather` 是源图像素单位的过渡宽度。它独立于每条路线的 `area`。为了使拖动能真正恢复已压暗区域，游戏使用未烘焙压暗的三态底图，明暗在运行时计算。编辑器画布近似显示日间效果，不模拟过渡羽化。
- 改战役对应：`campaign_region` 当前仅接受 `library`、`region_b`、`region_c`；这只是既有三段战役入口，不会创建新战役。每个区域只能对应一个地图选区；增加关联地标后，还需在对应区域配置它的探索站点。

手动编辑时，先复制一份 JSON 作备份。注意英文双引号、逗号和中括号；无效坐标、缺失地点引用、重复路线 ID 会被拒绝。地点和路线目前仍为试用数据，不能据此推断真实步行路线。

## 游戏流程与地图位置

基地选区读取本文件的 `routes`；`campaign_region` 只指定进入哪个已有区域。区域游玩顺序改在 `resources/campaign/regions/*.tres` 的 Stages 中，候选引用 `stops/` 的探索站点，站点再引用 `places/` 的共享地点。最后一站自动为终点。

地点资源用 Landmark 引用本文件地标，用 Offset 保留相对偏移；移动地图地标会带动所有关联地点。`campus_presentation.gd`从本次流程定义读取显示，按 Landmark／Offset 计算落点，不推断或修正旧坐标。正式区域名称和地点标签读取编辑器当前文字；背景、室内标记、站次及敌阵仍在 Godot 配置。详情见[区域流程配置](flow-authoring.md)。

游戏连线依据站次生成，地图编辑器路径拐点仅控制基地选区的展示线；两者无需逐点对应。故事落点仍是暂定位置，不代表实地步行路线。不为旧探索增加兼容或迁移；当前格式继续保存本次配置，不自动替换已保存的流程，不自动重置永久档。

## 地图与路线的数据校正及校验（2026-10-15）

地图编辑器与 Godot 路线编辑仍然分离。本次完成的是一次手动数据对齐与校验接入，没有合并两个编辑入口，也不会从关联地标列表自动生成探索站次。

当前三条路线以编辑器的关联地标为地域边界：图书馆线包含会堂、商业街、湿地、西侧教学区、西湖、图书馆；主楼线包含硕士宿舍、银桦餐厅、立人楼、银杏大道、东湖、主楼；体育场线包含本科宿舍、学子餐厅、品学楼、球场区、操场、体育场。六个图标不意味着六场战斗：仍为四站，会堂／商业街共享一站，部分站次提供互斥候选。流程顺序与候选归 Godot Stages／Choices；路径拐点仍是地图展示线，不决定战斗站次。

南门只在 `resources/campaign/prologue.tres` 的教学入口使用，既有地图可保留南门地标但不加入正式区域。终局使用独立 `finale.tres` 的图书馆核心。不要根据内部历史站点 ID `gate` 或背景图片判断地点，真实身份来自 Place Id／Landmark；同背景可由不同地点复用。

`campus_flow_rules.gd` 在真实资源校验及启动预检中核对区域的全部地标、缺失／跨区引用和南门用途；编辑器也拒绝区域重复映射。更新地标坐标／名称会同步显示，改变关联成员仍须同步配置 Godot 站点。专项命令与边界见 [CORE-02](core-02.md) 和 [验证页](verification.md#地图路线一致性)。本轮保留负责人地图 JSON 原字节，未生成底图或环境图。
