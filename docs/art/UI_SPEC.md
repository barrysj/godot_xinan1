# UI 视觉与实现规范

页面细则沿用 v0.3；跨领域风格见 [STYLE_BIBLE.md](STYLE_BIBLE.md)，生产与批准见[美术工作流](../pipeline/WORKFLOW.md)。

## 1. 核心定位

> **校园数字系统 + 图形化设计 + 分层赛博强度**

原则：

> **功能页耐看，高潮页出拳。**

---

## 2. 日常 UI

关键词：
- 白 / 浅灰
- 青蓝主强调
- 留白
- 清晰
- 稳定
- 轻数字感

允许：
- 少量斜切
- 少量节点
- 少量电路线
- 简洁标签
- 轻动画

品红与黄：
- 只做重点交互与提示

禁止：
- 每屏都像宣传海报
- 持续 glitch
- 高密度贴纸感
- 全页面高饱和撞色

---

## 3. 夜晚 UI

允许：
- 深色底
- 青 / 品红
- 发光边
- 更强标签
- 数据层叠
- 更明显斜切
- 更快速转场

---

## 4. 战斗 UI

允许：
- 强对比
- 大色块
- 技能数据轨迹
- 波形
- 网络节点
- 角色色彩身份强化
- 快速动画

---

## 5. 异常 UI

视觉强度最高：
- glitch
- 信息错位
- 数据流
- 文字篡改
- UI 侵入场景
- 高饱和青 / 品红 / 紫
- 故障提示
- 节点失控

前提：
> 核心操作必须可读。

---

## 6. 角色显示

按[角色规范](CHARACTER_SPEC.md)选择对应用途的形态，不通过缩放破坏比例感。

## 7. 核心页面

### 首页
包含：
- 主视觉
- 今日事项
- 校园动态
- 主导航
- 剧情 / 学习 / 探索 / 社团入口

### 课程表
要求：
- 真正可读
- 时间轴清晰
- 当前课程清楚
- 本周重点明确

### 任务板
可参考：
- To-do
- Kanban
- Sprint

但文案与状态要校园化；主线、支线、日常与进度应清楚。

### 关系网
推荐：
- 人物头像 = 节点
- 普通关系 = 青
- 亲密 / 情绪 = 品红
- 可行动事件 = 黄

### 校园地图
- 俯视或轻等距
- 建筑清楚
- 路径清楚，不制造信息噪音
- 图标统一

### 对话
- 按角色规范使用对话立绘
- 选项明确
- 重大分支可强化色块与动画

---

## 8. 组件规则

### 标题
- 粗体
- 几何感
- 一级层级可更张扬

### 按钮
- Normal / Hover / Selected / Disabled 清楚
- 高亮优先黄或品红

### 卡片
- 白底 / 深底
- 圆角克制
- 可用锐角 / 斜切品牌形状

### 图标
- 简洁
- 图形化
- 少量像素语言
- 避免复杂拟物

---

## 9. 响应式

目标分辨率与截图要求统一见[工作流](../pipeline/WORKFLOW.md#接入阶段)。

要求：
- 优先 Container / Anchor
- 核心信息不依赖固定像素坐标
- 图片裁切策略记录在 Manifest

---

## 10. 动效与排版

交互时长、推荐动作和禁用模式读取 [animation.json](../../data/visual/animation.json)，不在页面中重抄参数。动画不能阻塞核心操作，日常功能页保持稳定。

字体角色、字重及可读性约束读取 [typography.json](../../data/visual/typography.json)，间距读取 [spacing.json](../../data/visual/spacing.json)。一级标题可有几何与海报感；功能标题和正文稳定清楚；代码使用等宽角色，手写旁注只作氛围。中英文混排保持统一字重与节奏。

## 11. 组件建设与评审

按实际页面需要逐步复用或扩展 Theme、按钮状态、标签、图标、卡片、关系节点、任务板、对话框和地图图标，不为概念清单一次性建设整套 UI。

检查第一眼的辨识度、信息阅读顺序、日常页面是否过度张扬、高潮页冲击力和品牌色一致性。文字、按钮名称和对象渐进展示遵循项目协作规则。
