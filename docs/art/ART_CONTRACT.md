# Cyber Pop Campus 美术执行契约

本文件是 Codex 高频读取的精简视觉契约。

## 核心风格

> 精细 2D 卡通 + 校园赛博波普 + 图形化科技语言

视觉优先级：校园生活 → 计算机/电子科技身份 → 赛博波普图形语言 → 科幻/异常效果。

禁止：低像素主导、Q 版主导、廉价手游二次元、硬核脏乱赛博朋克、企业后台式 UI。

## 颜色

核心色从 `data/visual/colors.json` 读取，不要重复硬编码。

- 日常层：明亮中性底 + 科技青 + 少量品红/黄。
- 异常层：深色底 + 青/品红加强 + 黄作关键提示。
- glitch 只用于剧情异常。

## 形状语言

优先：斜切矩形、锐角标签、大色块、电路线折线、节点、点阵。  
避免：圆滚滚儿童 UI、复杂拟物、无意义装饰。

## 角色

- 地图：4.5～5.5 头身，非 Q 版。
- 立绘：6.5～7.5 头身。
- 必须像现代科技校园学生，不能像赛博佣兵。

## UI

UI 是校园数字思维的外显。信息可读性优先，强视觉只用于标题、重点交互与剧情强化。日常页面不得持续 glitch，不得自行发明品牌色。

## 资产政策

最终资产位于 `assets/art/`，元数据以 `docs/art/asset_manifest.yaml` 为准。

除非任务明确要求：
- 不要重新生成正式美术；
- 不要擅自替换已批准资产；
- 不要根据个人审美重做 UI；
- Manifest 已有尺寸/透明/Anchor/裁切信息时，不要重复分析图片。

## 实现政策

优先复用 Godot Theme、视觉 Token、已有组件，并将视觉参数数据化。不要在多个 Scene 复制相同色值，不要为同一功能创建平行 UI。

## Full Bible 读取条件

只有在建立新视觉系统、引入新场景大类、新角色表现系统、全局视觉重构或任务明确要求时，才读取 `STYLE_BIBLE.md`。普通实现任务禁止默认读取全文。
